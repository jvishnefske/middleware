# The Pico on Ethernet (W5500)

A build with `--features w5500` (`./build.sh rp2350 --features w5500`, or
`rp2040`) drives a WIZnet W5500 on SPI0. The wiring is the
W5500-EVB-Pico's, and a Pico or Pico 2 wired the same way also works:

| signal | GPIO |
|--------|------|
| MISO   | 16   |
| CS     | 17   |
| SCK    | 18   |
| MOSI   | 19   |
| RST    | 20   |
| INTn   | 21   |

Payloads cannot use these six pins or SPI0, even on GPIO 0–7. Both are
`Unsupported`. SPI1 and every other pin stay available to payloads.

## What it does

- **SPI clock.** The firmware asks for 20 MHz on SPI0. The divider gives
  about 18.75 MHz on the RP2350 and 15.6 MHz on the RP2040.
- **Boot.** The board resets the chip and checks its version. If no
  module answers, the boot log shows `w5500: init failed (...)` and the
  board keeps running: the serial link and mwctl work without the
  network.
- **MAC address.** It is `02:4d:` followed by four bytes from the node id
  (`rp_base::netid`).
- **DHCP.** The board requests a lease with host name `rp-<node id>`.
- **mDNS.** It announces `rp-<node id>._mw-node._tcp.local` with
  `board=pico-w5500` or `pico2-w5500`. It withdraws the record when the
  PHY link or the lease goes, and re-announces when both are back.
- **MAC filter.** The driver turns the W5500's MAC filter on.
  `NoMacFilter` turns it off so that mDNS multicast reaches the board.
  The cost is that the chip takes every frame on the segment into its
  16 KiB buffer, and the stack drops the ones that are not for the board.
  On a busy LAN, frames can be lost. See the hardware checks in design.md
  D53.

## Finding the board

```
avahi-browse -rt _mw-node._tcp        # from any host on the LAN
avahi-resolve -n rp-<id>.local
```
