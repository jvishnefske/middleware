# Vendored JSON schemas for kubeconform

`scripts/check-manifests.sh` checks the manifests that `mw-service` renders
(`--print-manifests`, the goldens under `service/tests/golden/`) against
these schemas. It runs kubeconform with `-strict` and never goes online. A
document whose kind has no schema here fails the check: it is not fetched
and it is not skipped. These files were downloaded once, on 2026-10-31, and
are not regenerated by any build step.

## Kubernetes 1.31 (core objects)

The four files at the top level are `serviceaccount-v1.json`,
`service-v1.json`, `deployment-apps-v1.json` and
`poddisruptionbudget-policy-v1.json`. They come from the
`v1.31.0-standalone-strict` directory of yannh/kubernetes-json-schema, at
commit `47163ead3738a996c3e30be9691bb37b8071d9d3`, via
`https://raw.githubusercontent.com/yannh/kubernetes-json-schema/<commit>/v1.31.0-standalone-strict/<file>`.
They are the strict variant, so every object refuses unknown fields.

## Istio (CRDs)

The Istio schemas are `security.istio.io/authorizationpolicy_v1.json` and
`networking.istio.io/destinationrule_v1.json`. They come from
datreeio/CRDs-catalog at commit `3eb90d47aba8d61919d4419dd38301536e32a94b`,
via `https://raw.githubusercontent.com/datreeio/CRDs-catalog/<commit>/<group>/<file>`.
The catalog generates them from the upstream Istio CRDs with
openapi2jsonschema and sets `additionalProperties: false` throughout. The
lab runs Istio 1.30.6. The `v1` versions of both CRDs are stable API, and
every field the renderer emits (`selector.matchLabels`, `action`,
`rules[].from[].source.principals`, `host`,
`trafficPolicy.tls.mode`) has been in them since `v1beta1`.

## SPIRE

There is no SPIRE schema. The renderer emits no SPIRE object, because the
lab's istiod gives every injected pod its SPIRE identity through the
`spire` injection template.

## Updating

To update, download the same paths at a newer commit or Kubernetes version.
Record the new commits here, regenerate `SHA256SUMS` (the script checks every file against it), and run `scripts/check-manifests.sh`. The script
deliberately feeds misspelt fields to kubeconform and expects them to be
refused, so it fails if a replacement schema stops being strict.
