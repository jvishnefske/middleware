# Changelog

## Unreleased

### mwctl opens a PTY (H7)
- `mwctl --port <pty>` works: ENOTTY from the RTS/DTR calls (open and `reset`) is tolerated as in `mw_gateway::io::open_serial` (RG28); other modem-line errors stay fatal. Test-only dev-dependency `libc` (already in Cargo.lock).

### posix-node announces itself on mDNS; `mwctl scout` browses it (D27–D39)
- mw-posix-node: new `MW_POSIX_NODE_MDNS` = `off` (default) | `on` | a unicast IPv4 address (`config::MdnsMode`). When on, `mdns_node::run` announces the shared `mw/node` record (`_mw-node._tcp`) as `posix-<node id>` on host `posix-<node id>.local`: the node's address (routed to 224.0.0.251, or the pinned one), SRV port 0, TXT `id`, `chip`, `board` (`unknown` without a device tree), `fw`, `sender` and, only for a `tcp`/`tls` router that is not loopback, `zenoh` (cut at `?`/`#`). It binds UDP 5353 beside avahi (`SO_REUSEADDR`/`SO_REUSEPORT`), re-checks the address every 15 s, retries failures (2 s to 60 s, 30 s after a conflict), never fails the node, and on SIGTERM is told to stop first and sends its goodbye (within 2 s) while the rest of the node shuts down. posix-node enables `middleware/mdns` (no new crate). Deployments opt in, e.g. NixOS `services.mw-posix-node.environment.MW_POSIX_NODE_MDNS = "on"`; with avahi off, open UDP 5353.
- middleware: `MdnsAnnouncerBuilder::multicast_interface(Ipv4Addr)` (`IP_MULTICAST_IF`); unset by default.
- mwctl: new optional feature `mdns` (with `zenoh`): `scout` also browses `_mw-node._tcp` with a one-shot querier for the scan's duration. New `MDNS` column and `mdns` rows (`scout::MdnsNode`, `Row::mdns`, `merge_mdns`, `MAX_MDNS`); the count line gains `, N announced on mDNS` (in every build). Records join a Zenoh row by `sender`, else by `id`, only as its sole claimant (two or more claims on one row attach none: `conflict: N records`, `Row::mdns_conflict`, each claimant its own `mdns` row); they never overwrite Zenoh cells. `just lan` uses `--features zenoh,mdns`. Limits: the replies are unicast from port 5353 to an ephemeral port, which a default-deny host firewall drops; off Linux, LAN answers are refused (the on-link subnets are read from `/proc/net/route`).

### posix-node serves its sys keys over Zenoh (PN21–PN27)
- mw-posix-node: `zenoh_sys` (on by default; `MW_POSIX_NODE_ZENOH_SYS=off` turns it off) declares one queryable, `@mw/node/<sender id>/sys/**`, and forwards the served keys to the device thread over a new mesh link (`DeviceParts::mesh`, `shell::spawn_device` takes it); `mesh_gate` decides them first: description keys in any trust state, everything else claimed-only, commits and binds signed, start/stop as signed control requests for `node_id[0..6]` with the counter persisted in the trust record (`Service::accept_control`). Each Zenoh requester is its own transfer owner (not authenticated); an unsigned commit no longer ends a transfer over Zenoh. A wildcard `@mw/node/*/sys/info` gets `sys/info`.
- Behaviour: the node's Zenoh session is now a **client** of `MW_ZENOH_ROUTER` (`session_config`) with its zid derived from the node id (`node_id::zenoh_id`, `STABLE_ZENOH_ID`), so its sender id survives restarts. A peer node was unreachable from peer tools through a router. A client fails to start while its router is down (systemd restarts it).
- `Service` gained `set_origin`, `origin`, `loader_owner`, `accept_control` and staging for `Air` origins; `Controller::mesh_request`.
- Review fixes: a Zenoh start/stop also needs a counter above the gateway's control counter store and saves there (one counter for `gw/sys` and Zenoh, `DeviceParts::shared_control`; `shell::spawn_device` takes `DeviceParts`); `ControlStore::save` is serialized in the process; notes from a Zenoh request go to `tracing`, not `sys/log` (`Note::BindDenied` for a refused bind); a query body is sized before it is copied, and the node session uses 4 KiB batches and a reassembly limit of a frame and 4 KiB.
- middleware: `zenoh_wire::{POSIX_ZENOH_ID_DOMAIN, posix_zenoh_id, posix_sender_id, sender_id_of_zid}` (the first two with `trust` or `zenoh`); the `zenoh` feature now pulls in `sha2`.
- mwctl: over `--zenoh` the control target defaults from `sys/info` (`zlink::target_for`), and a posix-node's reported node id must give the `--node` addressed (`TargetMismatch` otherwise); the `--node`/`--target` help explains the ids. mw-posix-node's dev-dependency on mwctl enables `zenoh` (the shipped mwctl is unchanged).

### Signed updates with hardware-held keys (TK1-TK8, E26, ZN5)
- Trust keys come in two kinds: Ed25519 (unchanged on the wire) and ECDSA P-256 (`loader::trust::KeyKind`, `PublicKey::{Ed25519, P256}`; a 33-byte compressed SEC1 claim, a 38-byte `sys/trust/info`), because TPMs and PIV cards sign P-256 only. Signatures stay 64 bytes (P-256 raw r‖s over SHA-256), so commit, control and firmware bodies are unchanged; a device verifies with the pinned key's algorithm (`verify_signature`), payloads and `fw_ota` firmware commits alike. Feature `trust` adds `p256` (no std, no alloc). Breaking: `PublicKey` is an enum (`PublicKey::Ed25519(bytes)` where `PublicKey(bytes)` was), `KEY_LEN` is `ED25519_KEY_LEN` / `P256_KEY_LEN` / `KEY_MAX`.
- `ControlOp` gains `FwReboot`, `FwConfirm`, `FwAbort` (3-5) for signed firmware controls over a network.
- Trust record format 3 (`esp_base::trust_store`, 68 bytes: a kind byte and a 40-byte key slot); formats 1 and 2 load as Ed25519 and migrate on the next save.
- Cost (TK3): 13-33 KB of code per firmware, no RAM; one P-256 verify needs 4.3-4.6 KB of stack, less than the Ed25519 verify every firmware already ran (7.6-8.3 KB; `scripts/verify-stack/run.sh`).
- mwctl: a `Signer` abstraction with key files and PKCS#11 tokens (`cryptoki`; `--pkcs11 <LABEL>` everywhere `--key` is taken, `key new|pub --pkcs11`, `key init-token`; module, token and PIN from `PKCS11_*` in the environment or `~/.env`, PINs never on a command line). Token signatures are normalised to low S and verified before use. Tests run the token path on SoftHSM2.
- The release key `mw-release` is P-256, generated inside the release workstation's TPM 2.0 (tpm2-pkcs11 token `mw`, not extractable); public key in `keys/mw-release.pub`.
- ESP8266 (E26): built with `trust` (claim, signed commits, `sys/trust/*`), trust record at `0x140000`.
- RT1050 (ZN5): over Zenoh a claimed board takes staged payload uploads with a signed commit, firmware updates with a signed commit, and signed `start`/`stop`/`fw reboot|confirm|abort`; transfers belong to the requester that began them (`Service::set_origin`). The board declares one per-node `sys/**` queryable (`zenoh_lite::ZenohLite::declare_node_prefix_queryable`, `declare_plain_queryable`), seven declarations instead of twelve. mwctl feature `zenoh` (off by default): `--zenoh <ENDPOINT>` / `--zenoh-listen <ENDPOINT>` with `--node <ID>` (and `--target <MAC>`); `fw update` there reboots, waits for the trial and confirms, each control signed with a fresh counter.
- Web: parses and claims P-256 keys and verifies their signatures (WebCrypto ECDSA, `decompressP256`); a device pinned to a hardware key tells the user to sign with mwctl.
- On hardware (ESP32-S3, 2026-11-17): TPM-signed payload accepted; unsigned, other-key, replayed, older and corrupted uploads refused; the trust record survives a reboot (TK6).
- Not yet on hardware: the Zenoh updates on the EVKB (the board's SWD is unresponsive and it is claimed by an older key); the A/B firmware updaters for ESP32/C3/S3, RP2040 and ESP8266 (TK8) are not started.

### i.MX RT1050-EVKB sensor routes and gaps (SC7, SC8)
- `firmware-imxrt`: payload source routes on the board. ### 0.6: updates through the MCU gateway (RG20–RG26)

### Key-value persistence (KV1-KV10)
- New `kv` module (always built, `no_std`, no heap): the `KvStore` trait (async) and `KvStoreSync` (blocking), with `Blocking` adapting one to the other. `Revision` stamps every write from one counter per store (from 1, strictly increasing, never reused). `Expect::{Any, Absent, Exact}` makes a put or delete compare-and-swap. `KvError::{Conflict, BufferTooSmall, TooLarge, Full, Backend}`; no error changes the store. Scans run in key byte order after an exclusive cursor and are bounded; `Scan` says whether the end was reached. `KvLimits` states the largest key and value.
- `kv::table::KvTable<N, K, V>`: fixed-capacity, heap-free, sorted RAM store; the reference implementation.

### Phases on real boards (M7, Q23; S12, E25, V20)
- `sys/info` capability bits (`loader::Caps`, `DeviceInfo::caps`): a little-endian `u32` after the node id, bit 0 `Caps::SERVE` = requests on keys the payload serves reach its `on_request`; other bits reserved. ### Payloads serve requests: ABI 5 (M1–M6)

### Payload SPI and I2C on more boards (V14–V19, E24)
- RP base (`firmware-rp/`): `spi_open` / `spi_transfer` / `dma_read` and `i2c_open` / `i2c_transfer` work on the Pico 2 (the RP2040 build compiles the same drivers but runs no payloads). SPI bus 0 lands on SPI0 or SPI1, whichever controller the payload's SCK / MOSI / MISO select in the chips' GPIO function table (`rp_base::periph::func`, identical on both chips; e.g. SPI0 SCK 18, MOSI 19, MISO 16); CS is any output pin, driven low for the whole transfer; clocks from 1.93 / 2.31 kHz to 40 MHz, never faster than asked; transfers up to 4092 bytes are pumped through the FIFOs by the controller loop (no DMA) and complete with `DmaDone`. I2C bus 0 is SDA GP4 / SCL GP5, bus 1 SDA GP6 / SCL GP7 (internal pull-ups), 10 kHz to 1 MHz, blocking; NACK, arbitration loss and the per-transfer time bound (at most 237 ms) are `Transport`, address-only probes `Unsupported`. The controllers are driven through embassy-rp's PAC (embassy-rp's drivers take pins by type and wait without bounds); every decision (function tables, pin claims, I2C timing and command plan, SPI divider and pump, time bounds) is in the host-tested `rp_base::periph`. Bus pins are exclusive: `gpio_*` on them is `Busy`, and a bus cannot take another bus's or a payload GPIO pin (`Busy`); stop, trap or upload resets the controllers and frees the pins. The `rp2040` feature now enables `embassy-rp/unstable-pac`. RP2350 static RAM 436 KB (the 4 KiB SPI buffer).
- esp-base (`firmware/`): I2C bus 0 on the ESP32-S3 at SDA GPIO 5 / SCL GPIO 6 (`chip::ESP32S3`'s `i2c0`), the ESP32's driver and claims, up to 400 kHz. `Bus0::open` now sets a per-byte software timeout on both chips (`esp_base::periph::i2c`), since esp-hal's defaults leave a stuck bus unbounded on the S3. ### RP2350 A/B firmware OTA integration (`firmware-rp/`, Y12–Y13)
- The RP2350 build serves `sys/fw/*` with `middleware::fw_ota::FwService` on `rp_base::ota::platform::RpPlatform`, an `FwPlatform` over any NOR flash and a boot ROM seam (`rp_base::ota::rom::Rom`). `rp_base::ota::AbUpdate` (the `FwUpdate` backend) starts the updater at boot and answers `Unavailable` when it cannot (no partition table). **Breaking (crate-internal):** `fw_update::FwUpdate` is now `FwUpdate<F>` and gets the flash, a `FwContext` (node id, root of trust, `SelfTest`) and the request; `fw_update::keys` is `middleware::fw_ota::keys` (seven keys).
- No `unsafe` and no ROM call but `reboot`: embassy-rp has `get_sys_info` and `explicit_buy` only as `unsafe fn`, and rp235x-hal (safe `boot_info`) cannot link beside embassy-rp (duplicate `__INTERRUPTS`). The booted slot comes from QMI `ATRANS0`, the trial flag from the running image's TBYB flag, and the buy is the firmware's own rewrite of the image's first sector (TBYB bit cleared) with interrupts masked, then `Watchdog::stop`.
- Flash map (Pico 2): partition table 0x000000 (8 KiB), slot A 0x002000 and slot B 0x180000 (1528 KiB each, partitions 0 and 1, B linked to A), update record 0x2FE000 (two sectors), payload store 0x300000 and trust 0x340000 unchanged. Reads go through a new untranslated XIP window (QMI `ATRANS1`, `rp_base::flash::Window`), because the boot ROM maps only the running slot at 0x10000000; the flash driver is declared 8 MiB for it.

- `build.sh rp2350 [--version MAJOR.MINOR]` now writes `rp-base-rp2350-V-update.bin`/`.uf2` (for `mwctl fw update`) and `rp-base-rp2350-V-factory.uf2`/`.bin` (partition table, the image bought in slot A, slot B and the record erased; family `absolute`) with the new host tool `rp-image` (feature `image-tool`); the partition table is built in Rust (`rp_base::ota::table`). The old single RP2350 UF2 (image at offset 0, absolute block) is gone. design.md has the factory flashing procedure.
- Self-test gating `sys/fw/confirm`: USB configured (embassy-usb handler), payload store and trust record open.
- RP2350 static RAM 432 KB (was 416 KB).
- **Security — fail closed on an unreadable trust record** (V13, Y16): if the trust record cannot be read at boot (either sector unreadable, or the region unusable), payload `begin`/`chunk`/`commit` and `sys/trust/claim`, and firmware `sys/fw/begin`/`chunk`/`commit`, answer `Unavailable` instead of being decided as on an unclaimed device (which accepted any unsigned image). `FwContext::trust` is `Option<TrustState>`. `info`, `sys/trust/info`, start/stop, `sys/fw/abort` and `sys/fw/reboot` still work; `sys/fw/confirm` is held back by the self-test, so such a trial reverts. The boot log says "payload and firmware installs refused".

### A/B firmware OTA for the RP2350 (Y1–Y11)

## 0.5.0

### Migration from 0.4
Breaking changes, in the order a 0.4 user meets them. Each is detailed in the sections below.
- **`Handler::handle` takes a `&Request`.** `fn h(key: Key<'_>, req: &[u8], out: &mut [u8])` becomes `fn h(r: &Request<'_>, out: &mut [u8])`, reading `r.key`, `r.body` and the new `r.meta` (`RequestMeta { sender, principal, deadline_ms }`). Closures: `|r: &Request<'_>, out: &mut [u8]| ...`, or wrap them in `transport::handler_fn` to fix the argument types. `grpc::responder::run_handler` takes a `RequestMeta` argument. In tree, the ESP base firmware's `dispatch::handle_request` now takes a `Request`.
- **`HandlerError` is `#[non_exhaustive]`** and gains `Unavailable` (code 6) and `DeadlineExceeded` (code 7). Matches outside the crate need a wildcard arm. Unknown codes still decode as `Internal`; a 0.4 peer decodes codes 6 and 7 as `Internal`.
- **`Requester` implementors implement `request_with(key, body, response, &RequestOptions)`** instead of `request`; `request` is now a provided method with `RequestOptions::DEFAULT`, so callers are unchanged. `RequestOptions { timeout, target }`, `Target::{Any, Node}`.
- **`Subscriber` implementors declare `const DELIVERY: Delivery` and `const LIMITS: Limits`** (both required). A type implementing both `Publisher` and `Subscriber` names `<T as Publisher>::LIMITS`.
- **`SampleMeta` has a `gap` field.** Struct literals add `gap: None`, or use `SampleMeta::NONE` / `SampleMeta::from_sender(..).with_seq(..)`.
- **`loader::DeviceInfo` has a `node` field.** Struct literals add `node: None`. The encoding only appends bytes: 0.4 hosts read 0.5 devices and the other way round.
- **Serial link.** `SerialLink<IO>` is now `SerialLink<IO, const I: usize = INBOX_BYTES>`: the default keeps publications read during a request (1 026 more bytes inside the link); `SerialLink::<_, 0>::with_inbox(io)` keeps none, as 0.4 did. `serial::link::DELIVERY` is `DropNewest` (was `Block`). `RECV_BUF_LEN` is 1 024 (was 1 033); larger buffers still work.
- **gRPC.** `GrpcSubscriber` queues locally and drops the oldest samples when the application falls behind (`GrpcTransport::with_queue_depth`, default 64; 0.4 read the stream directly), and reports `SampleMeta::gap`. `bus::ITEM_OVERHEAD` is 12 (was 10) and `grpc::MAX_PAYLOAD` is 4 MiB − 140 (was − 138); gap items go only to clients that ask with `mw-gap: report`, so 0.4 clients see the 0.4 wire format. `UNAVAILABLE` and `DEADLINE_EXCEEDED` now map to the new `HandlerError` variants instead of `Internal`. `GrpcTimeout` and friends live in `grpc::timeout` (still re-exported by `istio`). Plain `GrpcTransport` refuses `Target::Node` with the new `GrpcError::UnsupportedTarget`; use `grpc::mesh::MeshClient` to target a node.
- **Zenoh.** Delivery is `Block`: publications use congestion control Block and a slow subscriber back-pressures the publisher (0.4 published with Zenoh's default congestion control, which drops). `ZenohError` is `#[non_exhaustive]`. Publication attachments grow to 16 bytes and reply errors carry the replier's id: 0.5 reads 0.4 peers' attachments and errors; a 0.4 subscriber still receives 0.5 samples but without sender and sequence. Requests no longer use Zenoh's default consolidation.
- **Payload platform** (changed since 0.4.0 outside the transport contract): `wasm_host::Device::route_source` takes a `Source` (was a `SourceKind`); `wasm_host::Limits` has `max_stack_bytes` and `max_call_depth` (struct literals add them or `..Limits::default()`); `LoadError::OutOfMemory`, `wasm_abi::events::EventKind::{RouteFrames, RouteDropped, RouteStopped}`, `mw-payload`'s `irq::Event` route variants and `PixelFormat::Jpeg` are new arms for exhaustive matches; `PixelFormat::bytes_per_pixel` returns `Option<u32>`. `wasm_abi::ABI_VERSION` is 4; ABI 1–3 payloads load unchanged.
- **ESP base firmware trust record format 2** (over-the-air updates, O17): the first trust save on 0.5 firmware (a claim, a commit raising `min_version`, or an accepted signed start/stop) writes a format-2 record; format 1 still loads. Downgrading the firmware to 0.4 after that is a rollback: 0.4 reads format 1 only, so it falls back to the older format-1 record in the other sector or, once both sectors hold format 2, to Unclaimed (claimable again over serial). Crate-internal: `dispatch::Context` gained `staging` and `node`, `Action::Erase` gained `stop`, `TrustStore` stores a `Persisted { trust, control }`.
- **`mwctl` over ESP-NOW** (new in 0.5): `start`, `stop` and `upload --start` with `--espnow` need `--key` (signed control requests); serial use is unchanged.
- **New since 0.4.0, nothing to migrate:** the `discovery`, `dns`, `mdns` and `transport::memory` modules and the `dns-sd`, `memory` and `mdns` features. If you used the unreleased `mdns` module from the main branch: `mdns::ServiceDiscovery` is replaced by `discovery::Browse` on `MdnsSocket` (its old methods are the inherent `query`, `recv_response`, `try_recv_response`); the codec moved to `dns::wire` (`mdns::wire` re-exports it); `MdnsSocketBuilder` is no longer `Copy` and its setters are not `const`; `MdnsError` and `WireError` are `#[non_exhaustive]`.

### 0.5 core contract (breaking; K1–K15, L1–L15)
- **Transport contract** (`transport`, now split into `transport::meta`, `transport::pubsub` and `transport::reqrep`, all re-exported from `transport` and the crate root):
  - **Breaking — `Handler`.** `handle(&mut self, req: &Request<'_>, response: &mut [u8]) -> Result<usize, HandlerError>`. `Request { key, body, meta }` carries `RequestMeta { sender, principal, deadline_ms }` (principal: an authenticated name such as a SPIFFE URI; deadline: milliseconds left when the handler is called). Migration: `fn h(key: Key<'_>, req: &[u8], out: &mut [u8])` becomes `fn h(r: &Request<'_>, out: &mut [u8])` with `r.key` and `r.body`; closures become `|r: &Request<'_>, out: &mut [u8]| ...` or `transport::handler_fn(|r, out| ...)`, which fixes the argument types.
  - **Breaking — `HandlerError`** is `#[non_exhaustive]` and gains `Unavailable` (code 6) and `DeadlineExceeded` (code 7); `HandlerError::ALL` lists every variant; unknown codes still map to `Internal`. Matches outside the crate need a wildcard arm (`mwctl` and `protocol-wasm` name an unknown status "Unknown"). gRPC maps them to and from `UNAVAILABLE` and `DEADLINE_EXCEEDED` (previously both came back as `Internal`).
  - `Requester::request_with(key, body, response, &RequestOptions)` is the required method; `request` keeps its signature as a provided method using `RequestOptions::DEFAULT`. **Breaking for implementors:** implement `request_with` instead of `request`. `RequestOptions { timeout, target }` with `Target::{Any, Node(SenderId)}`. Timeouts: the memory backend, Zenoh (query timeout) and gRPC (`grpc-timeout` plus a local deadline, `DEADLINE_EXCEEDED`) honour them; the serial link and BLE GATT client have no clock and document that the caller bounds the call. `Target::Node` is `UnsupportedTarget` on Zenoh and gRPC (new error variants) and ignored on point-to-point links.
  - New `Gather::request_each(key, body, buf, &options, max_replies, on_reply)`: every reply (`Reply { sender, result }`) to a callback returning `Flow::{Continue, Stop}`, bounded by count and time.
  - **Breaking — `Subscriber`** requires `const DELIVERY: Delivery` (`Overflow::{DropNewest, DropOldest, Block}`, `per_sender_order`) and `const LIMITS: Limits`. Declared in tree as released: serial link (since its inbox), ESP-NOW (`espnow::DELIVERY`), BLE GATT client and BLE advertising (`ble::advert::ADVERT_DELIVERY`, no per-sender order) `DropNewest`; Zenoh `Block`; gRPC and memory `DropOldest`. A type implementing both `Publisher` and `Subscriber` now names `<T as Publisher>::LIMITS`.
  - **Breaking — `SampleMeta`** gains `gap: Option<u16>` (samples known lost before this one); struct literals need it or use `SampleMeta::NONE`, `SampleMeta::from_sender(..).with_seq(..).with_gap(..)`. Existing backends report `gap: None`. New `dedup::SeenTable::check` / `check_stream` and `dedup::SeqCheck` compute gaps from 8-bit wrapping sequences; `SeenTable::observe` is unchanged.
  - New `Split` trait (`Tx<'a>: Publisher`, `Rx<'a>: Subscriber`), implemented by the serial link over a `Duplex`, ESP-NOW over `RadioHalves` and BLE `AdvertisingLink` (below).
  - New in-process backend `transport::memory` (feature `memory`, std + tokio timers): `MemoryBus`, `MemoryNode` (Publisher, Subscribe, Requester, Gather), `MemorySubscriber`, `MemoryResponder`, `MemoryDiscovery`. Integration tests get it through the crate's self dev-dependency.
  - `typed`: `Client::request_with`, `TypedHandler` (decoded request + `RequestMeta` → encoded response), `TypedBrowser` and `encode_txt` (a typed service description in TXT entry `m`).
  - `grpc::responder::run_handler` takes a `RequestMeta` argument.
- **Service discovery** (`discovery`, new, always built, `no_std`, no heap): `ServiceKind`, `Endpoint`, `Service`, `Event::{Up, Down}`, the `Announce` and `Browse` traits, `Directory<N>` (pure TTL cache: observe, expire, lookup, refresh at 80 %), and `beacon::PubSubDiscovery` with the versioned `disc/<kind>` beacon format. Kinds map to DNS-SD types with `record::dns_sd_type` (`cam/jpeg` → `_cam-jpeg._tcp`).
- **Breaking — `mdns::ServiceDiscovery` is removed.** `MdnsSocket` implements `discovery::Browse` (browse an exact kind; events instead of raw responses). Its 0.4 trait methods are inherent methods: `browse(service_type)` → `query(service_type)`, `recv` → `recv_response`, `try_recv` → `try_recv_response`. `MdnsError` is non-exhaustive (new `UnsupportedFilter`, `Record`).
- **DNS codec moved** to `dns::wire` (always built); `mdns::wire` re-exports it, and `MDNS_PORT` / `MDNS_GROUP_V4` moved to `mdns`. New: `MessageWriter` (PTR, SRV, TXT, A, AAAA with name compression), `encode_query_for` (any type, recursion desired), `TextName`, `TxtWriter`, `Txt::new`, `Message::flags` / `rcode`. A message with more than `MAX_RECORDS` (64) resource records is now refused (`WireError::TooManyRecords`), bounding the instance join against hostile peers. `WireError` is non-exhaustive.
- New features: `dns-sd` (unicast DNS-SD in `dns::unicast`, below) and `memory`. New dependency: `heapless` 0.9 (no default features).

- **Zenoh** (`zenoh`, Z9–Z16; all ten conformance cases pass in `tests/zenoh.rs` over loopback sessions):
  - `request_with` uses `RequestOptions::timeout` as the query timeout, falling back to `with_timeout` (5 s default). Zenoh's own `Timeout` error reply is no longer mistaken for a responder's `Internal` error: a timed-out request is `NoReply`.
  - `Target::Node(id)` is supported (`ZenohError` is `#[non_exhaustive]`; an interim `UnsupportedTarget` variant never shipped): a `ZenohResponder` also declares `@mw/node/<zid16>/<key>` (new `zenoh::node_key`), and a node without a responder fails with `NoReply` at once.
  - `ZenohTransport` implements `Gather` (`QueryTarget::All`, no consolidation; each reply names its replier). Requests no longer use Zenoh's default consolidation, so the first reply returns as soon as it arrives.
  - Handlers see `RequestMeta::sender` (the requester's session id hash) and `deadline_ms` (the requester's timeout, minus time queued), carried in a new query attachment; `principal` stays `None`. Replies carry the replier's id (reply attachment; reply-error payloads are now the code byte plus 8 id bytes, and a bare code byte still decodes).
  - **Behaviour change — delivery is `Block`** (was declared `DropNewest`): Zenoh's FIFO blocks when full and `publish` now uses congestion control Block, so a slow subscriber back-pressures the link and the publisher instead of losing samples. New `with_queue_depth` (default 256, `DEFAULT_QUEUE_DEPTH`) and `queue_depth`. See `zenoh::subscriber` for the caveats (head-of-line blocking; Zenoh closes a link blocked past `wait_before_close`, 5 s).
  - `SampleMeta::gap` is reported, exact per key: sequences are now per key per transport value (a clone starts new streams), and the publication attachment grows to 16 bytes with a stream id (kind 2). 0.4 attachments (kind 1) still decode, without gaps.
  - New `ZenohDiscovery` (`ZenohTransport::discovery`): `Announce` as a record queryable plus a liveliness token on `@mw/svc/<kind>/<instance>` (record in the beacon encoding), `Browse` as a liveliness subscriber with history (`Up` after fetching the record, `Down` when the token goes, including when the announcer's session closes). New `ZenohError` variants `InvalidInstance`, `Record`, `NotBrowsing`.
  - Spoofing hardening (Z17, Z18): a `Target::Node(id)` request or gather drops replies whose replier id is not `id`; a discovery record fetch now waits for every reply, ignores replies on other keys or for another kind/instance, and refuses the service with the new `ZenohError::ConflictingRecords` when two records differ (it used to take the first decodable one). Trust model, documented in `zenoh` and `zenoh::discovery`: session ids and attachments are self-asserted (`Reply::sender` included); authenticated identity needs Zenoh ACLs/authentication on `@mw/svc/**` and `@mw/node/**`, which middleware does not configure.
  - Code split into `zenoh::{wire, subscriber, responder, discovery}`; `ZenohSubscriber`, `ZenohResponder` and `ZenohDiscovery` are re-exported from `zenoh`.

### gRPC / Istio (G10–G14, I6–I8)

### Unicast DNS-SD against Kubernetes cluster DNS (L16–L26)
- New `dns::unicast::UnicastDnsSd` (feature `dns-sd`, tokio UDP) implements `discovery::Browse` by polling the cluster DNS for the SRV records Kubernetes publishes per named Service port: one endpoint per SRV (one per pod of a headless Service), named by the target's first label, `Endpoint::Socket` from A/AAAA glue or follow-up A then AAAA queries, else `Endpoint::Host`; no node id. `browse` takes an exact kind or a prefix over the mapped kinds.
- `UnicastDnsSd::builder(map)`: `nameserver(addr)` (else the first of `/etc/resolv.conf` or `resolv_conf(ResolvConf)`), `bind`, `timeout`, `attempts`, `schedule`; `build().await`. Queries carry RD, EDNS(0) for 1232 bytes and a fresh id per attempt; replies are accepted only from the nameserver with the query's id and question. A truncated reply is `UnicastError::Truncated` (no TCP fallback); NXDOMAIN is an empty Service.
- Pure core: `ResolvConf::parse` (nameserver, search, domain, ndots/timeout/attempts; `namespace()` and `cluster_domain()` from a pod's search list); `ServiceMap` (kind → Service, namespace, port name; `srv_name` builds `_<port>._tcp.<svc>.<ns>.svc.<domain>`, default domain `cluster.local`); `answer::{check_reply, srv_answer, address_answer}`; `Tracker` (Up/Down diffs between answers, refresh Ups at 80 % of the reported TTL so a `Directory` keeps live endpoints) and `Schedule` (re-resolve at 80 % of the smallest TTL, clamped).
- Spoofing hardening (L25, L26): each query attempt uses a new socket on a fresh ephemeral port, connected to the nameserver, with an id from the OS CSPRNG (`dns::unicast::query_id`; new optional dependency `getrandom` 0.3, already in the lockfile, enabled by `dns-sd`). Skipped datagrams no longer end an attempt (`MAX_STRAY_DATAGRAMS` is removed); only the timeout does. The builder's `bind` now takes an `IpAddr` (the port is always ephemeral), and `local_addr()` is replaced by `bind_addr()`.
- `dns::wire` (additive): `MessageWriter::edns(udp_payload_size)`, `TYPE_OPT`, `FLAG_TC`.
- `tests/dns_sd.rs` runs the discovery conformance cases and the resolver against a stub DNS server on 127.0.0.1 (`tests/dns_sd/stub.rs`).

### 0.5 Embedded transports, ESP base firmware (K11, S8–S11, B11, A15, N15, N16, E17–E20)
- **Serial link** (`serial::link`):
  - **Inbox (S8).** Publications read while `request_with` or `serve_one` waits are kept in order in an inbox of `I` bytes inside the link (new const generic, `SerialLink<IO, const I: usize = INBOX_BYTES>`; `INBOX_BYTES` = 1026, one maximal publication; each entry costs its raw frame + `INBOX_ENTRY_OVERHEAD` (2) bytes) and returned first by `recv`, `try_recv`, `Filtered`, `SerialRx` and `next_frame`. ### Over-the-air updates: signed control, staging beside the running payload (O14–O19)
- Security fix (high): over ESP-NOW (unauthenticated, spoofable source MAC) anyone in range of a claimed device could stop or restart its payload (`sys/payload/stop|start`, or a `begin`, which stopped it) and abort transfers. Now over the air `start` and `stop` need a **signed control request** and a `begin` no longer touches the running payload. Serial is unchanged.
- Security fix (medium): the over-the-air policy checked the unsigned-commit rule before transfer ownership, so a non-owner's unsigned commit aborted the owner's transfer. Ownership is now checked first (`InvalidRequest`, loader untouched); only the owner's own unsigned commit ends its transfer.
- `middleware::loader::trust`: new `SignedControl` (`[counter u64 LE][signature 64]`, 72 bytes), `ControlCounter`, `ControlOp` (1 start, 2 stop), `control_message` (29 bytes: `b"mw-control-v1\0" || op || target MAC 6 || counter u64 LE`), constants `CONTROL_TAG`, `TARGET_LEN`, `CONTROL_MESSAGE_LEN`, `SIGNED_CONTROL_LEN`, and (feature `trust`) `TrustState::accept_control` (pinned key, `verify_strict`, counter strictly above the last). Golden vector in the tests, reproduced by mwctl. `Command::parse` still takes `start`/`stop` with empty bodies only.
- ESP base firmware, `esp_base::ota`: `admit` takes `Facts` (trust state, last control counter, own MAC) and returns `Admission::{Dispatch, Control { counter }}`; new refusals `UnsignedCommit` (was `Unsigned`), `UnsignedControl`, `ControlRefused`. The controller saves an accepted counter with the trust record before acting (`Internal` and no action if that fails) and dispatches the key with an empty body. Logs: `trust: signed sys/payload/stop accepted, counter N`, `ota: ... refused: control signature invalid ...`.
- ESP base firmware, `esp_base::dispatch`: `Context::staging` (set for requests over the air): a `begin` is `Action::Erase { len, stop: false }` and leaves the status alone, so the running payload keeps running while the inactive slot is erased and written; `Action::Activate` now stops the old payload (`stops_payload`); new `Action::stops_before_storage`, `State::stopped`, `after_storage_failure`; `State::storage_failed` keeps a running payload's status (only `Loading` returns to resting); `State::with_control` / `control` (a claim resets the counter to 0). **Breaking (crate-internal):** `Action::Erase` gained `stop`, `Context` gained `staging`; the ESP8266 firmware is updated. Logs: `ota: staging into the inactive slot; the payload keeps running`, `ota: new image active; stopping the payload that ran the old one`.
- ESP base firmware, trust record format 2 (60 bytes: format-1 fields, then the last accepted control counter u64, CRC-32 over bytes 0..56). Format-1 records still load (counter 0) and the next save migrates to format 2 in the other sector; saves never lower the counter for the same key. `TrustStore` stores a `Persisted { trust, control }`; `lowers_min_version` became `lowers`. The boot log reports the control counter.
- `mwctl --espnow`: `start`/`stop --key <KEYFILE> [--counter N]` and `upload --key ... --start` sign control requests for the target MAC (default counter: Unix time in ms); `upload`/`start`/`stop` over the air without `--key`, and `start`/`stop --key` over serial, are usage errors; a `Denied` start/stop is explained. `Device::start_signed`, `stop_signed`, `UploadOptions::start_auth`, `sign::sign_control`, `sign::counter_at`. `Cmd::Start`/`Cmd::Stop` carry `key` and `counter`.
- Firmware host lint: `cargo clippy --lib --all-targets -- -D warnings` passes again (`camera::extract` uses `as_chunks`; the `esp-base` binary has `required-features = ["shell"]`, so host commands skip it instead of failing on the missing ESP crates).
- On hardware (ESP32-S3 + ESP8266 bridge): the format-1 record migrated in place; unsigned, forged, replayed and stale control requests and an over-the-air `trust claim` were refused with the payload unaffected; begin + chunks without a commit, and a spoiled staged image, left the payload running; blink kept publishing through a 1.85 s staged upload of `bench` until its signed commit; non-owner unsigned commits in both directions were `InvalidRequest` while the owner's upload completed; the counter survived a reset.

### Over-the-air payload update over ESP-NOW (O1–O13)
- On the 0.5 contract (merged with the 0.5 work): `espnow::rpc::RpcRequester` implements `request_with`: `options.timeout` bounds the call (`Retry::within`: each attempt waits at most the budget, as many attempts as fit it, at least one; `None` keeps `attempts` × `timeout_ms`), and a `Target::Node` other than its one peer is the new `RpcClientError::WrongTarget` before anything is sent. `RpcResponder` hands its handler a `Request` naming the requester's MAC as `RequestMeta::sender` (unauthenticated). The firmware dispatches over-the-air requests with that sender; serial requests stay without one. The responder cache holds the longer 0.5 `sys/info` (node id included, `MAX_INFO_LEN`). The radio filters are 0.5's (`app/...` and `disc/...` received, a payload sends `app/...` only, E18); requests travel only as `MR` frames built by the radio task, which a payload's publishes (always `MW` samples) cannot produce.
- New `middleware::rpc` (always built, `no_std`, no heap): request/response frames for datagram radios (`MR` magic, version 1: kind, correlation id u16, addressee MAC, key + body or status + body; 250 bytes at most, key and body sharing 237, `CHUNK_DATA` = 217 image bytes per `sys/loader/chunk`), the requester rule `Call` (same id on every retransmission, bounded attempts, only the matching response from the asked peer to us) and the responder state `Replies<N, B>` (a repeat is replayed from a least-recently-used cache instead of running again; repeats while one runs are dropped; a request in flight 10 s is abandoned). Publication receivers skip `MR` frames as foreign.
- New `espnow::rpc` (feature `espnow`): `EspNowUnicast` (a radio that sends to one peer), `RpcRequester` implementing `Requester` (with a `Delay` for its timeout) and `RpcResponder` implementing `Responder`, tested over an in-memory air that loses, duplicates and reorders frames.
- ESP base firmware (`espnow`): the radio task taps `MR` frames off the radio, answers repeats from its cache and hands new requests addressed to it to the controller as `Port::Radio` requests from the sender's MAC; responses go unicast (requesters registered as driver peers, at most four, least recently used replaced). New pure `esp_base::ota`: over the air an unclaimed device refuses everything, a claimed one accepts only `sys/info`, `sys/trust/info`, `sys/loader/begin|chunk|commit` (commits signed only; unsigned ends the transfer) and `sys/payload/start|stop`, never `sys/trust/claim`. Serial and radio share one loader: the `begin`'s requester owns the transfer, a `begin` from the other side takes it over, and a non-owner's `chunk`/`commit` is `InvalidRequest` without touching it. Over-the-air begin/commit/start/stop and every refusal are logged on `sys/log`; request counters (`espnow rpc: ...`) are logged on change. `esp_base::radio` gains `Peers`, `RpcCounters` and the responder constants.
- New `tools/espnow-bridge/esp8266`: an ESP8266 Arduino sketch that is a dumb USB↔ESP-NOW radio (channel 1, 460800 baud, COBS + CRC-16 frames: `Send`, `Recv`, `Hello`, `Query`, `Stats`, `Sent`; bounded queues, counted drops). `tools/espnow-bridge/check.sh` runs the C++ codec's host test against the Rust golden frames and compiles the sketch.
- `mwctl --espnow <MAC>`: `info`, `trust info|claim`, `upload` (217-byte chunks, signed commit), `start`, `stop` over ESP-NOW through the bridge on `--port` (new `mwctl::bridge`, `mwctl::air::AirLink`, and the `link::Endpoint` trait both links implement; `Device` is generic over it). It prints the bridge's MAC and counters first and the request, retransmission and unacknowledged-send counts last; `upload` now reports its time and rate. `monitor` and `reset` are refused with `--espnow`.
- On hardware (ESP32-S3 + ESP8266 bridge): signed upload and start over the air, refusals of unclaimed, unsigned, stale, older and `trust claim` requests, and both directions of a `begin` taking the loader over; about 14 KB/s (`bench.wasm`, 23 072 bytes in 1.62 s) with no retransmission.

### Payload heap: eager translation and a start-time heap check (W10)
- Fixes a halt on the conagotchi badge (ESP32-S3, radio on): `cam_jpeg_view` (30.9 KB) started, then a few seconds later wasmi's lazy translation of a not yet called function failed to allocate (`memory allocation of 608 bytes failed` in the translator's `ControlFrame` stack) and the allocation-failure panic halted the chip. Measured on the host, lazy translation added about 74 KB (64-bit) after the load.
- `wasm-host` translates every function eagerly at load (`CompilationMode::Eager`); a first call no longer pays translation fuel (`w4_fuel_stats_record_every_call` now asserts it costs the same as the second). A call that runs out of fuel is counted as its whole budget even when wasmi leaves a few units.
- `wasm-host`: new `Limits::max_stack_bytes` (default `DEFAULT_STACK_BYTES`, 4 KiB; allocated in full on the first call, never grows) and `Limits::max_call_depth` (default `DEFAULT_CALL_DEPTH`, 32), set with `Limits::with_stack`; exceeding either traps with a stack overflow. Every example runs with 1 KiB and 12. The DMA copy buffer and subscription list are reserved at load; new `LoadError::OutOfMemory` if that fails. **Breaking:** `Limits` has two more public fields (struct literals need them or `..Limits::default()`), and exhaustive matches on `LoadError` need the new arm.
- `wasm-host`: loading in two steps, `Compiled::new(wasm, limits)` then `Payload::instantiate(compiled, device)` (`Payload::load` does both), so a caller can free the image in between.
- `wasm-host`: `Limits::load_heap_needed(image_len)`, an upper bound on the heap from compiling to the last call: the larger of compiling (image + module + translator buffers) and running (module + linear memory cap + value stack + call frames + fixed host state). Model and constants in the new pure module `wasm_host::heap`, scaled by pointer width and fitted to the examples measured on 64-bit and 32-bit (i686) hosts. 32-bit figures (peak / bound): blink 112 / 122 KB, cam_stream 115 / 125 KB, cam_view 141 / 143 KB, cam_jpeg_view 183 / 192 KB (its module alone is 94 KB).
- New tests: `tools/payload-sim/tests/heap.rs` (builds and runs every example under the badge's limits with a counting allocator, `peak_alloc`, and checks the bound against the compile, instantiate and run peaks; `cam_jpeg_view` must decode a frame) and `wasm-host/tests/alloc.rs` (after the deepest call, later calls allocate nothing). Both run without the libtest harness.
- ESP base firmware: `sys/payload/start` (and the autostart) first checks the free heap against the payload's bound plus `start::HEAP_MARGIN` (4 KiB, the allocator's overhead) and refuses before allocating anything, logging e.g. `payload start failed: not enough heap: needs N B (M B bound + 4096 B margin), F B free`; the request is answered `Internal` and the payload state is `trapped`, as for other start failures. The image is freed between compiling and instantiating. The boot log reports `heap: N B free after boot`, and a successful start `payload loaded (L bytes): heap F B free, needed at most N B`. New pure module `esp_base::start` (`check_heap`, `HeapShort`).
- ESP32-S3: `heap_main` 128 → 152 KiB (heap 200 → 224 KiB), main stack about 70 → 46 KiB, still above the 31 KiB a payload load needs and the badge's 40 KiB check.
- Known limit: on the badge `cam_jpeg_view` needs 195 886 bytes free (bound plus margin); the ESP32-S3 heap has 180 240 beside the 48 KiB radio budget, so it starts only if the radio uses at least about 16 KB less than budgeted. Otherwise it is refused with the message above instead of halting the chip.

### WASM JPEG decoder (`payloads/jpeg`, J1–J10)
- New payload library `mw-jpeg` (`payloads/jpeg`, `no_std`, no heap, no floats, `#![forbid(unsafe_code)]`): an incremental baseline JPEG decoder to RGB565 big-endian (or RGB888) strips for the badge's GC9A01. Grayscale and YCbCr 4:4:4 / 4:2:2 / 4:2:0, restart intervals, any size up to 2048×2048; progressive, arithmetic, lossless, hierarchical, 12-bit, CMYK and multi-scan files are `Error::Unsupported`. `Decoder::new`/`start` parse the markers; `decode_blocks(n)`, `decode_mcus(n)` and `decode_mcu_row` do bounded work per call into the caller's strip and return `Step::{Partial, Row(Strip), Done}`; `Scale::Half` uses libjpeg's reduced 4×4 IDCT (240×240 → 120×120). The decoder is a 4 352-byte struct on wasm32 that borrows the JPEG per call; `Decoder::IDLE` is all zero for a `.bss` static. Integer `jidctint` IDCT and fixed-point colour conversion; chroma is replicated. Tested against a float reference with a test-time encoder, against libjpeg/ffmpeg fixtures (bit-exact for 4:4:4 and grayscale), and with 10 000 seeded corruptions.
- `examples/fuel_probe.rs`: a minimal payload decoding an embedded 240×240 4:2:0 frame (about 14 KiB of decoder code); on wasmi a 4:2:0 MCU costs about 57 000–75 000 fuel (39 000–51 000 at half scale) and `decode_blocks(.., 1)` at most about 41 000 once translated. Lazy translation charges the first `start` and decode calls about 36 000 and 33 000 extra.
- `payloads/Cargo.toml`: `mw-jpeg` builds with `opt-level = "s"` (less fuel and smaller than `"z"` here); `scripts/check-all.sh` runs its tests, clippy and docs and validates `fuel_probe` with `abi-check`.

### ESP base firmware: ESP-NOW and DMA routes (R11, R12)
- ESP-NOW on ESP32 and ESP32-S3 (feature `espnow`, on with those chips): esp-radio 1.0.0-beta.1 brings Wi-Fi up as an unassociated station on fixed channel 1 and runs the middleware `EspNowTransport` (port of the conagotchi badge's `EspNowLink`). Payload publishes on `app/...` keys are also broadcast; received `app/...` samples reach `on_message` or a sink route. Queues are bounded (TX 4, RX 8) and drop and count; losses are logged on `sys/log`. (`esp_base::radio`)
- Source routes (`route_source`, `TestPattern`): each chunk's ESP-NOW frame is written in place (radio header, key, chunk header, pattern bytes), one broadcast in flight at a time; late frames skip whole periods as `RouteDropped`. `Camera`, non-`app` keys and chunks over 167 bytes are `Unsupported`. (`esp_base::route::source`, `sources`)
- Sink routes (`route_sink` on bus 0): chunks on the key bypass `on_message` and are DMAed to SPI2 with the preamble (D/C per segment) at each frame start; the bus (`spi_open`, `spi_transfer`) and D/C pin (`gpio_*`, `gpio_irq`) are `Busy` to the payload while the route runs; a failed transfer stops the route with `RouteStopped`. `route_stat` and `route_stop` per the contract. (`esp_base::route::sink`, `table`)
- Memory, to make room for the Wi-Fi driver: ESP32 `heap_main` 112 → 80 KiB, WASM memory 128 → 64 KiB, max image 32 → 24 KiB; ESP32-S3 `heap_main` 176 → 128 KiB, memory 128 → 64 KiB, max image 80 → 32 KiB; both budget 48 KiB of heap for the radio (`Profile::radio_heap`, also in the boot log). Payloads built for one 64 KiB page or 1-byte pages are unaffected; two-page payloads no longer load on these chips.
- Fix: starting any payload on an ESP32 panicked (`Pin 34 is not an OutputPin`): releasing the pins routed the output signal to the input-only GPIO34–39. `PinBank::release_all` now skips the output side of pins without a driver (`Profile::can_output`).
- Fix: after any payload stopped (`sys/payload/stop`, a trap, or an upload), every later `spi_open` in that boot was `Unsupported` (seen as `cam_view` failing its bring-up with error -4 after `mwctl stop` / `mwctl start`). `SpiBus::close` called `reclaim`, which swapped the bus state for a placeholder and only put it back if a transfer had been running, so an idle bus dropped the SPI2 driver and its static DMA buffers instead of returning them. The parts are now held in the pure `esp_base::periph::dma_hw` state (`DmaHw`: idle or in the running transfer, by-value transitions in an `HwSlot`), so stopping while idle, during a payload transfer or mid sink-route write cancels what runs and returns them; starting while a transfer runs is `Busy` without dropping it.
- `build.sh esp32` sets `ESP_HAL_CONFIG_MIN_CHIP_REVISION=100` (esp-hal defaults to 300), so the firmware boots on v1.x silicon such as the ESP32-CAM.

- `SampleMeta::seq` stays `u8`; its docs say why and how to compare it.

### Serial and ESP-NOW subscriptions (0.3)
- `SerialLink` implements `Subscribe`; its subscriber `Filtered<'l, IO>` (was `Filtered<'l, 'k, IO>`) borrows the link and owns a `KeyFilterBuf<MAX_KEY_LEN>`. **Breaking:** `SerialLink::filtered` is removed; use `link.subscribe(filter).await` (never waits, never fails).
- `EspNowTransport` implements `Subscribe`, handing out a new `EspNowSubscriber<'s, 'a, R, K, F, P>` that borrows the transport, owns a `KeyFilterBuf<MAX_KEY>` and selects with it instead of the filter slots. A filter key over `MAX_KEY` is `EspNowError::Frame(FrameError::KeyTooLong)`.
- `EspNowTransport<'a, R, K, F, P = MAX_FRAME>`: the new const generic `P` sizes the frame kept after `BufferTooSmall`. The default keeps behaviour unchanged; `P = 0` saves about 250 bytes of RAM, and a sample that does not fit the caller's buffer is then dropped instead of kept. `P > MAX_FRAME` is a compile error.

### gRPC client identity (0.3)
- `GrpcTransport` has a client id (`client_id()`, `with_client_id(SenderId)`, `grpc::client::fresh_client_id()`), sent as `mw-client` metadata (`bus::CLIENT_HEADER`) on publish and subscribe. Delivered samples carry the publisher in `SampleMeta.sender`.
- **Behaviour change:** like Zenoh, a transport no longer receives its own publications (clones share the id). `with_local_delivery(true)` opts back in (`mw-self: deliver`, `bus::SELF_HEADER`).
- Wire: subscribers that send `mw-client` get items `[key_len][key][sender_len][sender][payload]` (`bus::encode_item_with_sender` / `decode_item_with_sender`); subscribers without it keep the 0.2 format and delivery. `grpc::MAX_PAYLOAD` drops by 9 bytes to 4 MiB − 138 (`bus::ITEM_OVERHEAD`).

### BLE advertising (0.3)
- `AdvertisingSubscriber<S, K, L, D, F = K>`: `F` bounds the filters separately from the `K` learned keys. Filters are stored as owned `KeyFilterBuf<L>`; `subscribe_key`, `unsubscribe_key` and `with_filter` take any `Filter<Q: AsKey>` (a `KeyFilter` or a `KeyFilterBuf`), and `filters()` lists them. `ShortIdTable` stores `KeyBuf<L>`, so `L` may not exceed `MAX_KEY_LEN` (checked at compile time).
- New `ScanQueue<R = 8>`: a bounded, no-heap, waker-based `Scanner` that a radio callback fills with `push_report(&mut self, &ScanReport) -> Result<Pushed, ScanQueueError>` (newest wins when full). `next_report` waits for a push and is cancel-safe; `try_next_report` and `pop_report` do not wait; `poll_report` returns an owned `QueuedReport` for callers that share the queue behind their own lock.
- `AdvertisingSubscriber` implements `Subscribe`, handing out an `AdvertisingSubscription` view that delivers only its filter's keys; also `subscription()`, `scanner()`, `company_id()`.
- `const fn`: `AdvertisingSubscriber::with_company_id`, new `AdvertisingPublisher::with_template` (and `template()`), `ScanQueue::new`, `ShortIdTable::capacity`. `Default` for `AdvertisingPublisher` and `AdvertisingSubscriber` when the radio type is `Default`, and for `ScanQueue`.

### WASM runtime and payload SDK (0.3)
- **Breaking:** `wasm_host::LoadError::Init(Trap)` is now `LoadError::Init { trap: Trap, log: InitLog }`. `InitLog` holds the last `INIT_LOG_LINES` (8) lines `init` logged before it trapped (`lines()`, `len()`, `is_empty()`, `dropped()`, `Display`); the error's `Display` appends them. Lines still go to `Device::log` as before.
- **Breaking:** `Payload::tick` returns `Result<Ticked, Trap>` (was `Result<(), Trap>`), with `Ticked::{Ran, NotDue, Disabled, NoTickExport}`. Callers that only check for `Err` compile unchanged; new pure `abi::tick_decision`.
- `payload-sim` prints the log lines of a trapping `init` before `load failed: ...`.
- `mw_payload::payload!` no longer emits `#[allow(unsafe_code)]`, so payload crates may use `#![forbid(unsafe_code)]`; all examples now do.
- `payloads/scripts/build-byte-pages.sh` passes `--remap-path-prefix` for `$HOME`, the cargo registry and the repository; new `scripts/check-reproducible.sh` checks that two builds from different directories are byte-identical (run by `check-all.sh`).

### Payload ABI 3 (PWM, ADC, I2C)
- `wasm_abi::ABI_VERSION` is 3. New imports `pwm_open`, `pwm_set`, `pwm_stop`, `adc_read`, `i2c_open` and `i2c_transfer` (synchronous write, repeated start, read; at most `periph::MAX_I2C` = 64 bytes each way). ABI 1 and ABI 2 payloads load unchanged.
- `wasm_abi::periph` gains `PwmSpec`, `PwmDuty`, `I2cConfig`, `I2cTransfer` and the limits `MAX_PWM_TIMERS`, `PWM_CHANNELS`, `PWM_FREQ_HZ`, `ADC_MAX`, `I2C_BUSES`, `I2C_FREQ_HZ`, `MAX_I2C`.
- `wasm_host::Device` gains `pwm_open`, `pwm_set`, `pwm_stop`, `adc_read`, `i2c_open` and `i2c_transfer`, defaulting to `Unsupported`.
- The payload SDK adds `pwm` (`SetDutyCycle`), `adc` and `i2c` (`embedded_hal::i2c::I2c`); new `examples/dimmer`.
- `payload-sim` simulates PWM, ADC (`!adc <pin> <value>`) and an I2C register device at 0x50.

## 0.2.0

Breaking release driven by the conagotchi badge (ESP32-S3), which binds every backend to real radios and found where the 0.1 traits made it work around the crate.

### Core (`transport`, `key`, `dedup`)
- `KeyFilter { Exact, Prefix }` selects a family of keys, matching segment by segment; keys themselves still have no wildcards. A new `Subscribe` trait creates subscriptions at runtime.
- `Sample` gains `meta: SampleMeta { sender: Option<SenderId>, seq: Option<u8> }`. Build samples with `Sample::new(..).with_meta(..)`.
- `Subscriber::try_recv` (required) returns an already-available sample without waiting.
- The trait docs now state the cancel-safety rules: what happens when `recv`, `serve_one`, `request` or `publish` is dropped, the rule that sequences advance before the first await, and what to do when the receive buffer is too small.
- `Publisher::LIMITS: Limits { max_key, max_payload, max_message, shared }` with `Limits::new` (independent), `Limits::shared` (one frame budget) and `Limits::fits`.
- New `dedup` module:
  - `SeenTable<K>` deduplicates per (sender, key), so senders on one key no longer suppress each other.
  - Public `Sequence`, `fnv1a32`, `fnv1a64` and `short_id` (shared by BLE and ESP-NOW).
- `rust-version = "1.88"`.

### Backends
- **BLE advertising:**
  - per-sender dedup;
  - `ShortIdTable` resolves 16-bit ids to learned keys and detects collisions;
  - dynamic and prefix filters on `AdvertisingSubscriber`;
  - `Scanner::try_next_report`;
  - `Advertiser` may time-share the advertising set;
  - `AdvertisingPublisher::advertiser(&self)`.
- **BLE GATT:**
  - `GattLink` is split into `GattServer` and `GattClient`, which carry connection lifecycle events;
  - `BleServer` and `BleClient` replace `BleTransport`;
  - the MTU is read per message;
  - the ATT buffer size is a const generic;
  - `serve_one` is cancel-safe, and a disconnect or a new request id discards a partial request;
  - `with_services` is removed.
- **ESP-NOW (new `espnow` feature, no_std):** the MW v1 broadcast frame, runtime filters, per-sender dedup, sender and sequence metadata, and cancel-safe receive. It was upstreamed from conagotchi.
- **Zenoh:**
  - implements `Subscribe` (a prefix maps to `k/**`);
  - a sender and sequence attachment;
  - no self-delivery by default (`with_local_delivery` turns it back on).
- **gRPC bus (wire change):** `Subscribe` with an `mw-filter: exact|prefix` header, and keyed stream items `[key_len][key][payload]`. The inherent `subscribe(Key)` is removed.
- **Serial link:** `try_recv`, cancel-safe receive and transmit cursors, `filtered(KeyFilter)`, and `RECV_BUF_LEN`.
- **wasm-host:**
  - `Limits { max_memory_bytes, fuel_per_call }` with `Limits::pages` / `Limits::bytes`;
  - modules with 1-byte custom pages are accepted;
  - wasmi uses `portable-dispatch`, so stack use stays bounded on xtensa.
- **esp-base:** chip profiles state memory in bytes; the `sys/info` wire format is unchanged.
