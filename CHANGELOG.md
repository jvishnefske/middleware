# Changelog

## Unreleased

### 0.5 core contract (breaking; K1–K15, L1–L15)
- **Transport contract** (`transport`, now split into `transport::meta`, `transport::pubsub` and `transport::reqrep`, all re-exported from `transport` and the crate root):
  - **Breaking — `Handler`.** `handle(&mut self, req: &Request<'_>, response: &mut [u8]) -> Result<usize, HandlerError>`. `Request { key, body, meta }` carries `RequestMeta { sender, principal, deadline_ms }` (principal: an authenticated name such as a SPIFFE URI; deadline: milliseconds left when the handler is called). Migration: `fn h(key: Key<'_>, req: &[u8], out: &mut [u8])` becomes `fn h(r: &Request<'_>, out: &mut [u8])` with `r.key` and `r.body`; closures become `|r: &Request<'_>, out: &mut [u8]| ...` or `transport::handler_fn(|r, out| ...)`, which fixes the argument types.
  - **Breaking — `HandlerError`** is `#[non_exhaustive]` and gains `Unavailable` (code 6) and `DeadlineExceeded` (code 7); `HandlerError::ALL` lists every variant; unknown codes still map to `Internal`. Matches outside the crate need a wildcard arm (`mwctl` and `protocol-wasm` name an unknown status "Unknown"). gRPC maps them to and from `UNAVAILABLE` and `DEADLINE_EXCEEDED` (previously both came back as `Internal`).
  - `Requester::request_with(key, body, response, &RequestOptions)` is the required method; `request` keeps its signature as a provided method using `RequestOptions::DEFAULT`. **Breaking for implementors:** implement `request_with` instead of `request`. `RequestOptions { timeout, target }` with `Target::{Any, Node(SenderId)}`. Timeouts: the memory backend, Zenoh (query timeout) and gRPC (`grpc-timeout` plus a local deadline, `DEADLINE_EXCEEDED`) honour them; the serial link and BLE GATT client have no clock and document that the caller bounds the call. `Target::Node` is honoured by Zenoh (per-node queryables) and by gRPC's `grpc::mesh::MeshClient`; plain `GrpcTransport` returns `GrpcError::UnsupportedTarget`, and point-to-point links ignore it.
  - New `Gather::request_each(key, body, buf, &options, max_replies, on_reply)`: every reply (`Reply { sender, result }`) to a callback returning `Flow::{Continue, Stop}`, bounded by count and time.
  - **Breaking — `Subscriber`** requires `const DELIVERY: Delivery` (`Overflow::{DropNewest, DropOldest, Block}`, `per_sender_order`) and `const LIMITS: Limits`. Declared in tree: serial link `Block`; ESP-NOW (`espnow::DELIVERY`), BLE GATT client, BLE advertising (`ble::advert::ADVERT_DELIVERY`, no per-sender order) and Zenoh `DropNewest`; gRPC and memory `DropOldest`. A type implementing both `Publisher` and `Subscriber` now names `<T as Publisher>::LIMITS`.
  - **Breaking — `SampleMeta`** gains `gap: Option<u16>` (samples known lost before this one); struct literals need it or use `SampleMeta::NONE`, `SampleMeta::from_sender(..).with_seq(..).with_gap(..)`. Existing backends report `gap: None`. New `dedup::SeenTable::check` / `check_stream` and `dedup::SeqCheck` compute gaps from 8-bit wrapping sequences; `SeenTable::observe` is unchanged.
  - New `Split` trait (`Tx<'a>: Publisher`, `Rx<'a>: Subscriber`); no implementations yet.
  - New in-process backend `transport::memory` (feature `memory`, std + tokio timers): `MemoryBus`, `MemoryNode` (Publisher, Subscribe, Requester, Gather), `MemorySubscriber`, `MemoryResponder`, `MemoryDiscovery`. Integration tests get it through the crate's self dev-dependency.
  - `typed`: `Client::request_with`, `TypedHandler` (decoded request + `RequestMeta` → encoded response), `TypedBrowser` and `encode_txt` (a typed service description in TXT entry `m`).
  - `grpc::responder::run_handler` takes a `RequestMeta` argument.
- **Service discovery** (`discovery`, new, always built, `no_std`, no heap): `ServiceKind`, `Endpoint`, `Service`, `Event::{Up, Down}`, the `Announce` and `Browse` traits, `Directory<N>` (pure TTL cache: observe, expire, lookup, refresh at 80 %), and `beacon::PubSubDiscovery` with the versioned `disc/<kind>` beacon format. Kinds map to DNS-SD types with `record::dns_sd_type` (`cam/jpeg` → `_cam-jpeg._tcp`).
- **Breaking — `mdns::ServiceDiscovery` is removed.** `MdnsSocket` implements `discovery::Browse` (browse an exact kind; events instead of raw responses). Its 0.4 trait methods are inherent methods: `browse(service_type)` → `query(service_type)`, `recv` → `recv_response`, `try_recv` → `try_recv_response`. `MdnsError` is non-exhaustive (new `UnsupportedFilter`, `Record`).
- **DNS codec moved** to `dns::wire` (always built); `mdns::wire` re-exports it, and `MDNS_PORT` / `MDNS_GROUP_V4` moved to `mdns`. New: `MessageWriter` (PTR, SRV, TXT, A, AAAA with name compression), `encode_query_for` (any type, recursion desired), `TextName`, `TxtWriter`, `Txt::new`, `Message::flags` / `rcode`. A message with more than `MAX_RECORDS` (64) resource records is now refused (`WireError::TooManyRecords`), bounding the instance join against hostile peers. `WireError` is non-exhaustive.
- New features: `dns-sd` (unicast DNS-SD in `dns::unicast`, below) and `memory`. New dependency: `heapless` 0.9 (no default features).
- `scripts/check-features.sh` checks that `discovery` and `dns::wire` are in the no-feature `thumbv6m-none-eabi` build, builds `dns-sd` and `memory` on the host, and asserts no embedded set enables a host feature.
- **Zenoh** (`zenoh`, Z9–Z16; all ten conformance cases pass in `tests/zenoh.rs` over loopback sessions):
  - `request_with` uses `RequestOptions::timeout` as the query timeout, falling back to `with_timeout` (5 s default). Zenoh's own `Timeout` error reply is no longer mistaken for a responder's `Internal` error: a timed-out request is `NoReply`.
  - `Target::Node(id)` is supported (supersedes `UnsupportedTarget` above for Zenoh; the variant is removed from `ZenohError`, which is now `#[non_exhaustive]`): a `ZenohResponder` also declares `@mw/node/<zid16>/<key>` (new `zenoh::node_key`), and a node without a responder fails with `NoReply` at once.
  - `ZenohTransport` implements `Gather` (`QueryTarget::All`, no consolidation; each reply names its replier). Requests no longer use Zenoh's default consolidation, so the first reply returns as soon as it arrives.
  - Handlers see `RequestMeta::sender` (the requester's session id hash) and `deadline_ms` (the requester's timeout, minus time queued), carried in a new query attachment; `principal` stays `None`. Replies carry the replier's id (reply attachment; reply-error payloads are now the code byte plus 8 id bytes, and a bare code byte still decodes).
  - **Behaviour change — delivery is `Block`** (was declared `DropNewest`): Zenoh's FIFO blocks when full and `publish` now uses congestion control Block, so a slow subscriber back-pressures the link and the publisher instead of losing samples. New `with_queue_depth` (default 256, `DEFAULT_QUEUE_DEPTH`) and `queue_depth`. See `zenoh::subscriber` for the caveats (head-of-line blocking; Zenoh closes a link blocked past `wait_before_close`, 5 s).
  - `SampleMeta::gap` is reported, exact per key: sequences are now per key per transport value (a clone starts new streams), and the publication attachment grows to 16 bytes with a stream id (kind 2). 0.4 attachments (kind 1) still decode, without gaps.
  - New `ZenohDiscovery` (`ZenohTransport::discovery`): `Announce` as a record queryable plus a liveliness token on `@mw/svc/<kind>/<instance>` (record in the beacon encoding), `Browse` as a liveliness subscriber with history (`Up` after fetching the record, `Down` when the token goes, including when the announcer's session closes). New `ZenohError` variants `InvalidInstance`, `Record`, `NotBrowsing`.
  - Code split into `zenoh::{wire, subscriber, responder, discovery}`; `ZenohSubscriber`, `ZenohResponder` and `ZenohDiscovery` are re-exported from `zenoh`.

### gRPC / Istio (G10–G14, I6–I8)
- **Caller identity.** `GrpcResponder` fills `RequestMeta`: `sender` from `mw-client` (requests now send it), `deadline_ms` from `grpc-timeout` (measured when the handler runs), `principal` from a configured `PrincipalSource` (new; default `None`). `ResponderService::with_principal_source(PrincipalSource::SidecarXfcc)` (feature `istio`) takes the SPIFFE ID from Envoy's `x-forwarded-client-cert` with the new pure `istio::peer_principal` (last element, quoting and escapes handled; `istio::is_spiffe_id`, `XFCC_HEADER`); use it only behind the sidecar. New `responder::call_meta`, `CallMeta`, `remaining_ms`.
- **Timeouts and status.** `GrpcTimeout`, `TimeoutUnit`, `GRPC_TIMEOUT_HEADER` and `MAX_TIMEOUT_VALUE` moved to the new `grpc::timeout` (built with `grpc` alone); `istio` re-exports them. `request_with` writes `grpc-timeout` with it, and a server's `CANCELLED` arriving after the deadline is reported as `DEADLINE_EXCEEDED`.
- **Breaking — subscriber delivery.** `GrpcSubscriber` reads its stream into a local queue (a spawned task; `GrpcTransport::with_queue_depth`, a power of two, default 64) and drops the oldest samples when the application falls behind; `SampleMeta::gap` is now `Some(n)` with the samples lost before each one, locally or to the bus's broadcast lag. A sample too large for the buffer is kept for a retry (previously dropped). Wire: `Subscribe` with `mw-gap: report` gets `[key_len][key][sender_len][sender][gap u16 BE][payload]` items (`bus::encode_item_with_gap`, `decode_item_with_gap`, `GapItem`, `GAP_HEADER`, `GAP_REPORT`); older clients are unchanged. `bus::ITEM_OVERHEAD` is 12 and `grpc::MAX_PAYLOAD` 4 MiB − 140 (was − 138).
- **Health.** New `grpc::health`: `grpc.health.v1.Health` `Check` / `Watch` hand-encoded on `RawCodec` (no prost): `health()` → (`HealthService`, `GrpcAnnouncer`), `HealthClient`, `HealthWatch`, `ServingStatus`, `HealthTable`, `health_name`. `GrpcAnnouncer` implements `discovery::Announce` (announce → `SERVING`, withdraw → `NOT_SERVING`); the Kubernetes Service object remains the real announcement. `GrpcServer::with_health` mounts it.
- **Mesh** (new `grpc::mesh`, feature `istio`): `MeshClient<N>` implements `Requester` and `Gather` over the endpoints of one kind in a `discovery::Directory`, through the sidecar or directly (`MeshDialer`), and honours `Target::Node` (`UNAVAILABLE` when no endpoint names the node; plain `GrpcTransport` still answers `UnsupportedTarget`); default bound `mesh::DEFAULT_TIMEOUT` (5 s). `MeshBrowse<B: Browse, N>` wraps any browser (unicast DNS-SD, mDNS, the in-process bus) and reports an endpoint `Up` only while its health `Watch` says `SERVING`. `endpoint_authority`, `targets`, `MeshBrowseError`.
- `tests/grpc.rs` runs every conformance case against gRPC over loopback (`conformance_cases::k15_grpc_*`, feature `istio`).

### Unicast DNS-SD against Kubernetes cluster DNS (L16–L26)
- New `dns::unicast::UnicastDnsSd` (feature `dns-sd`, tokio UDP) implements `discovery::Browse` by polling the cluster DNS for the SRV records Kubernetes publishes per named Service port: one endpoint per SRV (one per pod of a headless Service), named by the target's first label, `Endpoint::Socket` from A/AAAA glue or follow-up A then AAAA queries, else `Endpoint::Host`; no node id. `browse` takes an exact kind or a prefix over the mapped kinds.
- `UnicastDnsSd::builder(map)`: `nameserver(addr)` (else the first of `/etc/resolv.conf` or `resolv_conf(ResolvConf)`), `bind`, `timeout`, `attempts`, `schedule`; `build().await`. Queries carry RD, EDNS(0) for 1232 bytes and a fresh id per attempt; replies are accepted only from the nameserver with the query's id and question. A truncated reply is `UnicastError::Truncated` (no TCP fallback); NXDOMAIN is an empty Service.
- Pure core: `ResolvConf::parse` (nameserver, search, domain, ndots/timeout/attempts; `namespace()` and `cluster_domain()` from a pod's search list); `ServiceMap` (kind → Service, namespace, port name; `srv_name` builds `_<port>._tcp.<svc>.<ns>.svc.<domain>`, default domain `cluster.local`); `answer::{check_reply, srv_answer, address_answer}`; `Tracker` (Up/Down diffs between answers, refresh Ups at 80 % of the reported TTL so a `Directory` keeps live endpoints) and `Schedule` (re-resolve at 80 % of the smallest TTL, clamped).
- Spoofing hardening (L25, L26): each query attempt uses a new socket on a fresh ephemeral port, connected to the nameserver, with an id from the OS CSPRNG (`dns::unicast::query_id`; new optional dependency `getrandom` 0.3, already in the lockfile, enabled by `dns-sd`). Skipped datagrams no longer end an attempt (`MAX_STRAY_DATAGRAMS` is removed); only the timeout does. The builder's `bind` now takes an `IpAddr` (the port is always ephemeral), and `local_addr()` is replaced by `bind_addr()`.
- `dns::wire` (additive): `MessageWriter::edns(udp_payload_size)`, `TYPE_OPT`, `FLAG_TC`.
- `tests/dns_sd.rs` runs the discovery conformance cases and the resolver against a stub DNS server on 127.0.0.1 (`tests/dns_sd/stub.rs`).

### 0.5 Embedded transports, ESP base firmware (K11, S8–S11, B11, A15, N15, N16, E17–E20)
- **Serial link** (`serial::link`):
  - **Inbox (S8).** Publications read while `request_with` or `serve_one` waits are kept in order in an inbox of `I` bytes inside the link (new const generic, `SerialLink<IO, const I: usize = INBOX_BYTES>`; `INBOX_BYTES` = 1026, one maximal publication; each entry costs its raw frame + `INBOX_ENTRY_OVERHEAD` (2) bytes) and returned first by `recv`, `try_recv`, `Filtered`, `SerialRx` and `next_frame`. Before, they were discarded. A publication that does not fit is dropped and counted (`inbox_dropped()`, `inbox_len()`); `SerialLink::<_, 0>::with_inbox(io)` keeps nothing. **Behaviour change:** `serial::link::DELIVERY` is `Overflow::DropNewest` (was `Block`), per-sender order kept.
  - **Peer (S9).** `SerialLink::with_peer(SenderId)` / `peer()`: received samples carry the peer as `SampleMeta::sender` and `serve_one` handlers see it as `RequestMeta::sender`.
  - **Split (K11).** New `Duplex<R, W>` (a reading and a writing half as one stream, error `DuplexError`); `SerialLink<Duplex<R, W>, I>` implements `Split` into `SerialTx` (publisher, `send`) and `SerialRx` (subscriber, inbox first).
  - Received frames are now decoded in place in the splitter and copied to the caller's buffer in raw form: **`RECV_BUF_LEN` is `MAX_RAW_FRAME` (1024, was the 1033-byte wire frame)**, and `recv`, `next_frame` and `serve_one`'s `scratch` need only the raw frame. The link no longer needs a second frame-sized scratch for receiving.
- **ESP-NOW** (`espnow`): new `EspNowSend`, `EspNowReceive` and `RadioHalves<S, R>` (an `EspNowRadio`); `EspNowTransport<'_, RadioHalves<S, R>, ..>` implements `Split` into `EspNowTx` and `EspNowRx` (N16). Gaps are documented as never reported (N15).
- **BLE**: `GattServer::peer()` (default `None`, additive) is passed to `BleServer` handlers as `RequestMeta::sender` (B11). New `ble::advert::AdvertisingLink` (publisher + subscriber) implementing `Publisher`, `Subscriber` and `Split` into `AdvertTx` / `AdvertRx` (A15).
- **`sys/info` node id (S10, E17).** `loader::DeviceInfo` gains `node: Option<SenderId>`, encoded as 8 trailing bytes after the firmware name (`NODE_ID_LEN`, `MAX_INFO_LEN` = 81). Every decoder in tree (`DeviceInfo::decode`, used by `mwctl`, `protocol-wasm`/the web page and conagotchi) already ignored trailing bytes, so old hosts read new devices and the other way round. **Breaking for struct literals:** add `node: None`. `mwctl info` prints a `node:` line; `decodeDeviceInfo` returns `node` as 16 hex digits when present.
- **ESP base firmware:**
  - `dispatch::handle_request` takes a middleware `Request` (key, body, `RequestMeta`) instead of a key and a body; `Context` gains `node` (the chip's base MAC as `SenderId`), reported at the end of `sys/info`. The ESP8266 firmware passes `Request::new(key, body)` and no node id. (E17)
  - Radio policy: the transport has two filter slots, `radio::FILTERS` = `app/...` and `disc/...`; `goes_over_air` admits both, `carries_routes` keeps source routes on `app/...`, `is_beacon` marks beacons. `sys/...` still never crosses the radio. (E18)
  - Discovery (new pure `esp_base::radio::disc`): while a camera source route runs, the radio task broadcasts a `disc/cam/jpeg` beacon (instance `cam-xxxxxx`, node id the MAC, endpoint local, TXT `key=<route key>`, TTL 30 s) at the start and every 15 s, and a goodbye when the route stops (E19). Every device keeps a 4-record `discovery::Directory` of the beacons it hears and logs `disc: up cam/jpeg cam-aabbcc node 246f28aabbcc0000 ttl 30 s (1 known)`, `disc: updated ...`, `disc: down ... (goodbye, 0 known)` and `disc: down ... (expired)` on `sys/log`; refreshes are silent; beacons are not delivered to the payload (E20). `SourceTable::camera_key`.
- `tests/serial.rs` (feature `serial`): every applicable conformance case over an in-memory fake link pair, plus inbox and split tests (S11).
- **Security fixes** (review of the above):
  - ESP base firmware: a payload can no longer send `disc/...` over ESP-NOW. `radio::goes_over_air` (payload publishes, re-checked by the radio shell's `send`) and `carries_routes` (source routes) admit `app/...` only; `disc/...` is reserved for the radio task's own beacon. Beacons are still received. (E18)
  - ESP base firmware: directory records are bound to the frame's source MAC: a beacon declaring another node is refused, only a record's creator may update or withdraw it, and one sender holds at most `radio::disc::PER_SENDER` (2) of the 4 records; a full directory refuses new records instead of logging them. Refusals are counted (`Neighbours::refused`). The `disc: full, ...` log line is gone. (E21)
  - ESP base firmware: the `disc:` log lines escape radio-supplied kinds and instances (bytes outside printable ASCII, and `\`, as `\xNN`). (E22)
  - `mwctl`: `[log]` lines show control characters escaped instead of writing them to the terminal. (H3)
- ESP base firmware: the serial port links use no inbox (`SerialLink<_, 0>`, `shell::link::INBOX`): the port tasks never wait in `request_with`/`serve_one`, and the 2 KiB saved keeps the conagotchi badge's main stack above 40 KiB (45 032 B; 40 920 B with the default inbox). (E23)

### The real OV2640 behind `SourceKind::Camera` (R15)
- ABI (`wasm_abi::route`): a camera source's `route_source` config is 21 bytes, the 10-byte `SourceConfig` (must be JPEG: the size the payload set on the sensor, the period the shortest frame interval) followed by the 11 pins of the new `CameraPins` (D0..D7, VSYNC, HREF, PCLK; distinct; `CameraPins::AI_THINKER`). New `CAMERA_PINS_LEN`, `CAMERA_CFG_LEN`, `source_cfg_len`, `Source` (`TestPattern` / `Camera(CameraPins)`, `Source::encode`) and `parse_source`. **Breaking:** `wasm_host::Device::route_source` takes a `Source` instead of a `SourceKind`; `wasm_host` re-exports `Source` and `CameraPins`. The test pattern still takes exactly 10 bytes, so existing payloads are unchanged.
- ABI 3 PWM frequency ceiling raised from 1 MHz to 40 MHz (`periph::PWM_FREQ_HZ`) so a payload can clock a camera sensor; no request that was valid is refused.
- SDK: `Route::camera(key, &cfg, pins)`; `Route::source(SourceKind::Camera, ..)` is `InvalidArgument` (the camera needs its pins).
- ESP base firmware, ESP32 (the ESP32-CAM): ABI 3 PWM and I2C are implemented. Board pin map in `esp_base::chip` (`Profile::pwm_pin`, `i2c_pins`, `camera`): PWM timer 0 channels 0..3 on GPIO 0 (XCLK), 4 (flash LED), 13, 14 (LEDC high-speed timer 0; new pure `periph::pwm` plans the duty bits per frequency, 2 at 20 MHz); I2C bus 0 on SDA 26 / SCL 27 (I2C0, blocking, up to 400 kHz, open drain with pull-ups); other chips stay `Unsupported`. `periph::claims` gains the `Pwm`, `I2c` and `Camera` owners (`claim_pwm`, `claim_i2c`, `claim_camera`, `release`, `pins_of`); peripheral pins are refused to `gpio_*`, and GPIO0 driven as XCLK can never count as a BOOT press.
- ESP base firmware, ESP32: `SourceKind::Camera` captures with I2S0 in camera mode (slave, 8-bit parallel, receive FIFO mode 1) and its DMA into a 16 KiB ring (`DmaRxStreamBuf`), configured with esp-hal's I2S driver and single-bit register fields only (no `unsafe`). The new pure `esp_base::camera` extracts the samples from the DMA words (`extract`, `SampleMode`) and finds each JPEG (`Assembler`, `FF D8` … `FF D9` across any buffer split) into an 8 KiB frame buffer; the radio task captures when a frame is due (`Next::Capture` / `Due::Capture`, `SourceRoute::camera`, `SourceRoute::captured`, `SourceTable::captured`, `Feed`, `CaptureFault`) and sends it as ESP-NOW chunks copied from the frame buffer. Overflow, ring overrun or no frame within 600 ms drop the frame (`RouteDropped`). The ring and frame buffer come from the heap once, at the first camera route (`NoResources` if short). The first captures and every 16th are logged; the first captured frame of a boot and every 64th are mirrored on the serial links as `dbg/cam/jpeg` chunks.
- New example payload `cam_ov2640_stream` (ESP32-CAM): powers the OV2640 (PWDN low), clocks it at 20 MHz on PWM, checks its ID over SCCB (logs `sensor PID 0x26 VER 0x42`), soft-resets it and writes a 219-register table (derived from Zephyr's Apache-2.0 `ov2640.c`, with esp32-camera's JPEG clock: `CLKRC` 0, `R_DVP_SP` 8) for 240×240 JPEG at quality 15 from the centred 1200×1200 square, in slices of at most 32 writes, then starts `Route::camera` on `app/cam/jpeg` every 500 ms. Deploy the byte-pages build (`payloads/target/byte-pages/wasm32-unknown-unknown/release/cam_ov2640_stream.wasm`, 7 801 bytes, 6 144 bytes of memory). `cam_jpeg_stream` (fixtures) is unchanged.
- `payload-sim`: an OV2640 SCCB model at 0x30 on I2C bus 0; the camera route stays `Unsupported` (no image model). `tests/ov2640.rs` runs the payload's bring-up against it.
- `cam_jpeg_view`: a frame smaller than the one before first blacks out the border it does not cover (the old image stayed visible around it); image 25 714 → 26 353 bytes, memory unchanged. Redeploy its byte-pages build on the badge.

### Where a payload's time goes: `perf:` report, flash speed at boot, `bench` payload (E15, E16, P8)
- ESP base firmware (E15): while a payload runs, the controller times every payload operation (delivery, `on_irq`, `tick`) with the microsecond clock and reads its fuel from `Payload::fuel_stats`, as well as its waits and yields; the radio task adds its time on received frames. Every 5 s two `sys/log` lines report it, e.g. `perf: 5000 ms: wasm 4101 ms (82.0%), 652 calls, 6100k fuel, 1487k fuel/s busy; max op 12345 us 260k fuel` and `perf: msg 580/1100k/900 ms, irq 70/4900k/3200 ms, tick 2/100k/1 ms; wait 500 ms, yield 200 ms, host 199 ms; radio 120 ms, 1450 rx`. On by default (`esp_base::perf::ENABLED`); new pure module `esp_base::perf`.
- ESP base firmware (E16): the boot log names the SPI flash mode and clock from the bootloader's image header, e.g. `flash: DIO 40 MHz (bootloader header)` (new `esp_base::chip::FlashSettings`). espflash 4 writes DIO at 40 MHz unless told otherwise, which neither `build-images.sh` nor the badge's runner does; code, the WASM interpreter included, runs from flash through the instruction cache at that speed.
- New example payload `bench` (P8): measures the host's interpreter speed in fuel per second, alternating 1 ms-paced steps of integer mixing (196 564 fuel) and `mw-jpeg` decoding the fake camera's 240×240 frame 4 MCUs at a time (12 786 673 fuel per 62-step frame), and logs per workload every 5 s; it subscribes to `app/cam/jpeg` and only counts, to put the camera's message load on the host. Deploy its byte-page build (30 720 bytes of memory; heap bound below `cam_jpeg_view`'s). `tools/payload-sim/tests/bench.rs` keeps its fuel constants within 5 % of what it measures; `check-all.sh` builds, tests, lints and validates it.
- Investigation of `cam_jpeg_view`'s 9.8 s per frame on the badge (about 1.4 M fuel/s): see design.md, "Interpreter speed on the badge". Ruled out: the wasmi build profile (`opt-level` 3 instead of `"s"`/`"z"` leaves the handlers the same size and adds 145 KB) and the decoder's 1 ms pacing (under 1 % of a frame).

### cam_jpeg_view fits the badge; heap bound from the module's declared memory (W12, W13, J12, P7, E14, H2)
- `wasm-host`: the heap bound charges linear memory at what the module can reach, the smaller of the cap and its declared maximum (W12). New `Limits::heap_needed(&wasm)` (the bound for this image; `load_heap_needed(len)` stays the worst case for any image of that length), `abi::memory_decl` / `abi::MemoryDecl` (initial and maximum bytes from the memory section) and `abi::memory_reach`. A 1-byte-page module with initial = maximum is charged exactly its memory: the badge's `cam_jpeg_view` built with 57 344 bytes was charged the whole 64 KiB.
- ESP base firmware: a start checks the image length against the free heap, reads the image, then checks the full bound from the image (`Limits::heap_needed`) with the image buffer credited back (new `start::check_heap_holding`); a refusal frees the buffer. The refusal message is unchanged.
- No heap leak on refused or failed starts (W13): `wasm-host/tests/alloc.rs` now repeats a refused start, a compile error, a dropped `Compiled`, an `init` trap and a load-and-stop 20 times and requires every byte back. The 1 248-byte drop seen on the badge between two refused starts comes from ESP-NOW reception during the camera's flood (esp-radio's per-frame `Box`es and a receive `VecDeque` whose capacity never shrinks, the Wi-Fi driver's dynamic RX buffers), not from the start or upload path.
- `cam_jpeg_view` image 30 878 → 25 714 bytes (23.3 KB of code) and 15.0 M → 13.2 M fuel per frame in `payload-sim` (at most 259 985 in one call, was 294 354) (J12):
  - `mw-payload` (P7): `LogLine` and the `on_message` delivery copy cannot panic, and `LogLine::log` passes its bytes without `str::from_utf8`, so payloads link none of core's panic formatting. Every example shrinks (blink 5 467 → 1 972 bytes). `push_u32` now drops a number that does not fit whole instead of cutting its digits.
  - `mw-jpeg`: new default feature `half` (`Scale::Half`, the reduced IDCT, about 1 KB); without it `Decoder::start` returns the new `Unsupported::Scale`. **Breaking:** exhaustive matches on `Unsupported` need the new arm. `cam_jpeg_view` depends on it with `default-features = false`; `jpeg` is no longer a default member of the payload workspace, so a plain `cargo build --release` does not unify `half` back in.

  - `middleware::stream` chunk header parsing reads its `u32`s with `first_chunk`, without a panic path.
- `scripts/build-byte-pages.sh` takes `memory` and `stack` from a package's `[package.metadata.byte-pages]` when it builds that one package (the environment still wins). `cam_jpeg_view` sets 48 128 bytes (data and `.bss` 39 088 + 8 KiB stack, rounded up to 1 KiB; it overflows with 2 816 bytes of stack and runs with 3 072). `check-all.sh` builds it reproducibly, validates it, and also tests and lints `mw-jpeg` without default features. **Deploy `payloads/target/byte-pages/wasm32-unknown-unknown/release/cam_jpeg_view.wasm` on the badge**: it needs 164 291 bytes free (160 195 bound + 4 096 margin, 32-bit), about 24 KB below the 188 KB free after boot; the 64 KiB-page build needs 181 685. `tools/payload-sim/tests/heap.rs` measures the deploy build too (`cam_jpeg_view/b`).
- ESP base firmware (E14): the controller yields to the executor once per iteration of its running loop, and the radio task once per received ESP-NOW frame. A busy payload (cam_jpeg_view's 1 ms decode timer fires again during every decode call) or a flood that keeps esp-radio's queue non-empty kept its task from ever returning to the executor, starving the serial links: the start reply was never sent and `mwctl upload --start` stalled.

### Payload heap: eager translation and a start-time heap check (W10)
- Fixes a halt on the conagotchi badge (ESP32-S3, radio on): `cam_jpeg_view` (30.9 KB) started, then a few seconds later wasmi's lazy translation of a not yet called function failed to allocate (`memory allocation of 608 bytes failed` in the translator's `ControlFrame` stack) and the allocation-failure panic halted the chip. Measured on the host, lazy translation added about 74 KB (64-bit) after the load.
- `wasm-host` translates every function eagerly at load (`CompilationMode::Eager`); a first call no longer pays translation fuel (`w4_fuel_stats_record_every_call` now asserts it costs the same as the second). A call that runs out of fuel is counted as its whole budget even when wasmi leaves a few units.
- `wasm-host`: new `Limits::max_stack_bytes` (default `DEFAULT_STACK_BYTES`, 4 KiB; allocated in full on the first call, never grows) and `Limits::max_call_depth` (default `DEFAULT_CALL_DEPTH`, 32), set with `Limits::with_stack`; exceeding either traps with a stack overflow. Every example runs with 1 KiB and 12. The DMA copy buffer and subscription list are reserved at load; new `LoadError::OutOfMemory` if that fails. **Breaking:** `Limits` has two more public fields (struct literals need them or `..Limits::default()`), and exhaustive matches on `LoadError` need the new arm.
- `wasm-host`: loading in two steps, `Compiled::new(wasm, limits)` then `Payload::instantiate(compiled, device)` (`Payload::load` does both), so a caller can free the image in between.
- `wasm-host`: `Limits::load_heap_needed(image_len)`, an upper bound on the heap from compiling to the last call: the larger of compiling (image + module + translator buffers) and running (module + linear memory cap + value stack + call frames + fixed host state). Model and constants in the new pure module `wasm_host::heap`, scaled by pointer width and fitted to the examples measured on 64-bit and 32-bit (i686) hosts. 32-bit figures (peak / bound): blink 112 / 122 KB, cam_stream 115 / 125 KB, cam_view 141 / 143 KB, cam_jpeg_view 183 / 192 KB (its module alone is 94 KB).
- New tests: `tools/payload-sim/tests/heap.rs` (builds and runs every example under the badge's limits with a counting allocator, `peak_alloc`, and checks the bound against the compile, instantiate and run peaks; `cam_jpeg_view` must decode a frame) and `wasm-host/tests/alloc.rs` (after the deepest call, later calls allocate nothing). Both run without the libtest harness.
- ESP base firmware: `sys/payload/start` (and the autostart) first checks the free heap against the payload's bound plus `start::HEAP_MARGIN` (4 KiB, the allocator's overhead) and refuses before allocating anything, logging e.g. `payload start failed: not enough heap: needs N B (M B bound + 4096 B margin), F B free`; the request is answered `Internal` and the payload state is `trapped`, as for other start failures. The image is freed between compiling and instantiating. The boot log reports `heap: N B free after boot`, and a successful start `payload loaded (L bytes): heap F B free, needed at most N B`. New pure module `esp_base::start` (`check_heap`, `HeapShort`).
- ESP32-S3: `heap_main` 128 → 152 KiB (heap 200 → 224 KiB), main stack about 70 → 46 KiB, still above the 31 KiB a payload load needs and the badge's 40 KiB check.
- Known limit: on the badge `cam_jpeg_view` needs 195 886 bytes free (bound plus margin); the ESP32-S3 heap has 180 240 beside the 48 KiB radio budget, so it starts only if the radio uses at least about 16 KB less than budgeted. Otherwise it is refused with the message above instead of halting the chip.

### WASM JPEG decoder (`payloads/jpeg`, J1–J10)
- New payload library `mw-jpeg` (`payloads/jpeg`, `no_std`, no heap, no floats, `#![forbid(unsafe_code)]`): an incremental baseline JPEG decoder to RGB565 big-endian (or RGB888) strips for the badge's GC9A01. Integer `jidctint` IDCT and fixed-point colour conversion; chroma is replicated. Tested against a float reference with a test-time encoder, against libjpeg/ffmpeg fixtures (bit-exact for 4:4:4 and grayscale), and with 10 000 seeded corruptions.

### ESP base firmware: ESP-NOW and DMA routes (R11, R12)
- ESP-NOW on ESP32 and ESP32-S3 (feature `espnow`, on with those chips): esp-radio 1.0.0-beta.1 brings Wi-Fi up as an unassociated station on fixed channel 1 and runs the middleware `EspNowTransport` (port of the conagotchi badge's `EspNowLink`). Payload publishes on `app/...` keys are also broadcast; received `app/...` samples reach `on_message` or a sink route. Queues are bounded (TX 4, RX 8) and drop and count; losses are logged on `sys/log`. (`esp_base::radio`)
- Source routes (`route_source`, `TestPattern`): each chunk's ESP-NOW frame is written in place (radio header, key, chunk header, pattern bytes), one broadcast in flight at a time; late frames skip whole periods as `RouteDropped`. `Camera`, non-`app` keys and chunks over 167 bytes are `Unsupported`. (`esp_base::route::source`, `sources`)
- Sink routes (`route_sink` on bus 0): chunks on the key bypass `on_message` and are DMAed to SPI2 with the preamble (D/C per segment) at each frame start; the bus (`spi_open`, `spi_transfer`) and D/C pin (`gpio_*`, `gpio_irq`) are `Busy` to the payload while the route runs; a failed transfer stops the route with `RouteStopped`. `route_stat` and `route_stop` per the contract. (`esp_base::route::sink`, `table`)
- Memory, to make room for the Wi-Fi driver: ESP32 `heap_main` 112 → 80 KiB, WASM memory 128 → 64 KiB, max image 32 → 24 KiB; ESP32-S3 `heap_main` 176 → 128 KiB, memory 128 → 64 KiB, max image 80 → 32 KiB; both budget 48 KiB of heap for the radio (`Profile::radio_heap`, also in the boot log). Payloads built for one 64 KiB page or 1-byte pages are unaffected; two-page payloads no longer load on these chips.
- Fix: starting any payload on an ESP32 panicked (`Pin 34 is not an OutputPin`): releasing the pins routed the output signal to the input-only GPIO34–39. `PinBank::release_all` now skips the output side of pins without a driver (`Profile::can_output`).
- Fix: after any payload stopped (`sys/payload/stop`, a trap, or an upload), every later `spi_open` in that boot was `Unsupported` (seen as `cam_view` failing its bring-up with error -4 after `mwctl stop` / `mwctl start`). `SpiBus::close` called `reclaim`, which swapped the bus state for a placeholder and only put it back if a transfer had been running, so an idle bus dropped the SPI2 driver and its static DMA buffers instead of returning them. The parts are now held in the pure `esp_base::periph::dma_hw` state (`DmaHw`: idle or in the running transfer, by-value transitions in an `HwSlot`), so stopping while idle, during a payload transfer or mid sink-route write cancels what runs and returns them; starting while a transfer runs is `Busy` without dropping it.
- `build.sh esp32` sets `ESP_HAL_CONFIG_MIN_CHIP_REVISION=100` (esp-hal defaults to 300), so the firmware boots on v1.x silicon such as the ESP32-CAM.

### WASM runtime and payload SDK (0.3)
- **Breaking:** `wasm_host::LoadError::Init(Trap)` is now `LoadError::Init { trap: Trap, log: InitLog }`. `InitLog` holds the last `INIT_LOG_LINES` (8) lines `init` logged before it trapped (`lines()`, `len()`, `is_empty()`, `dropped()`, `Display`); the error's `Display` appends them. Lines still go to `Device::log` as before.
- **Breaking:** `Payload::tick` returns `Result<Ticked, Trap>` (was `Result<(), Trap>`), with `Ticked::{Ran, NotDue, Disabled, NoTickExport}`. Callers that only check for `Err` compile unchanged; new pure `abi::tick_decision`.
- `payload-sim` prints the log lines of a trapping `init` before `load failed: ...`.
- `mw_payload::payload!` no longer emits `#[allow(unsafe_code)]`, so payload crates may use `#![forbid(unsafe_code)]`; all examples now do.
- `payloads/scripts/build-byte-pages.sh` passes `--remap-path-prefix` for `$HOME`, the cargo registry and the repository; new `scripts/check-reproducible.sh` checks that two builds from different directories are byte-identical (run by `check-all.sh`).

### Payload ABI 3 (PWM, ADC, I2C)
- `wasm_abi::ABI_VERSION` is 3. New imports `pwm_open`, `pwm_set`, `pwm_stop`, `adc_read`, `i2c_open` and `i2c_transfer` (synchronous write, repeated start, read; at most `periph::MAX_I2C` = 64 bytes each way). ABI 1 and ABI 2 payloads load unchanged.
- `wasm_abi::periph` gains `PwmSpec`, `PwmDuty`, `I2cConfig`, `I2cTransfer` and the limits `MAX_PWM_TIMERS`, `PWM_CHANNELS`, `PWM_FREQ_HZ`, `ADC_MAX`, `I2C_BUSES`, `I2C_FREQ_HZ`, `MAX_I2C`.
- `wasm_host::Device` gains `pwm_open`, `pwm_set`, `pwm_stop`, `adc_read`, `i2c_open` and `i2c_transfer`, defaulting to `Unsupported`.
- The payload SDK adds `pwm` (`SetDutyCycle`), `adc` and `i2c` (`embedded_hal::i2c::I2c`); new `examples/dimmer`.
- `payload-sim` simulates PWM, ADC (`!adc <pin> <value>`) and an I2C register device at 0x50.

## 0.2.0

Breaking release driven by the conagotchi badge (ESP32-S3), which binds every backend to real radios and found where the 0.1 traits made it work around the crate.

### Core (`transport`, `key`, `dedup`)
- `KeyFilter { Exact, Prefix }` selects a family of keys, matching segment by segment; keys themselves still have no wildcards. A new `Subscribe` trait creates subscriptions at runtime.
- `Sample` gains `meta: SampleMeta { sender: Option<SenderId>, seq: Option<u8> }`. Build samples with `Sample::new(..).with_meta(..)`.
- `Subscriber::try_recv` (required) returns an already-available sample without waiting.
- The trait docs now state the cancel-safety rules: what happens when `recv`, `serve_one`, `request` or `publish` is dropped, the rule that sequences advance before the first await, and what to do when the receive buffer is too small.
- `Publisher::LIMITS: Limits { max_key, max_payload, max_message, shared }` with `Limits::new` (independent), `Limits::shared` (one frame budget) and `Limits::fits`.
- New `dedup` module:
  - `SeenTable<K>` deduplicates per (sender, key), so senders on one key no longer suppress each other.
  - Public `Sequence`, `fnv1a32`, `fnv1a64` and `short_id` (shared by BLE and ESP-NOW).
- `rust-version = "1.88"`.

### Backends
- **BLE advertising:**
  - per-sender dedup;
  - `ShortIdTable` resolves 16-bit ids to learned keys and detects collisions;
  - dynamic and prefix filters on `AdvertisingSubscriber`;
  - `Scanner::try_next_report`;
  - `Advertiser` may time-share the advertising set;
  - `AdvertisingPublisher::advertiser(&self)`.
- **BLE GATT:**
  - `GattLink` is split into `GattServer` and `GattClient`, which carry connection lifecycle events;
  - `BleServer` and `BleClient` replace `BleTransport`;
  - the MTU is read per message;
  - the ATT buffer size is a const generic;
  - `serve_one` is cancel-safe, and a disconnect or a new request id discards a partial request;
  - `with_services` is removed.
- **ESP-NOW (new `espnow` feature, no_std):** the MW v1 broadcast frame, runtime filters, per-sender dedup, sender and sequence metadata, and cancel-safe receive. It was upstreamed from conagotchi.
- **Zenoh:**
  - implements `Subscribe` (a prefix maps to `k/**`);
  - a sender and sequence attachment;
  - no self-delivery by default (`with_local_delivery` turns it back on).
- **gRPC bus (wire change):** `Subscribe` with an `mw-filter: exact|prefix` header, and keyed stream items `[key_len][key][payload]`. The inherent `subscribe(Key)` is removed.
- **Serial link:** `try_recv`, cancel-safe receive and transmit cursors, `filtered(KeyFilter)`, and `RECV_BUF_LEN`.
- **wasm-host:**
  - `Limits { max_memory_bytes, fuel_per_call }` with `Limits::pages` / `Limits::bytes`;
  - modules with 1-byte custom pages are accepted;
  - wasmi uses `portable-dispatch`, so stack use stays bounded on xtensa.
- **esp-base:** chip profiles state memory in bytes; the `sys/info` wire format is unchanged.
